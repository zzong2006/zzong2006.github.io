# A) ColBERT 개요

ColBERT(Contextualized Late Interaction over BERT)는 대규모 문서 컬렉션에서 관련 문서를 빠르고 정확하게 찾는 랭킹 모델이다. BERT 기반 모델의 높은 정확도를 유지하면서, 지연 상호작용(Late Interaction) 구조로 검색 속도와 계산 효율을 크게 개선했다.

## A.1) 지연 상호작용 (Late Interaction)

기존 검색 모델은 크게 두 방식으로 나뉜다.

* **Dense Retrieval**: 질의(query)와 문서를 각각 **벡터 하나**로 압축해 유사도를 계산한다.
	* 빠르지만, 문서 전체 의미를 벡터 하나에 담다 보니 세부 정보를 잃을 수 있다.
* **Cross-encoder**: BERT 같은 모델에 질의와 문서를 함께 넣어 단어 수준의 상호작용을 모두 계산한다.
	* 정확도는 매우 높다.
	* 모든 질의–문서 쌍마다 무거운 연산을 해야 해서 매우 느리다.

ColBERT 는 두 방식의 장점을 합친 지연 상호작용을 제안한다.

1. **독립적인 다중 벡터 인코딩**: 질의와 문서를 각각 따로 BERT 인코더에 통과시킨다.
	* 단일 벡터로 압축하지 않고, **각 토큰(단어 또는 하위 단어)의 벡터를 모두 유지**한다.
	* 즉 문서 하나가 벡터 집합으로 표현된다.
2. **지연된 상호작용과 MaxSim 연산**: 따로 인코딩한 벡터는 검색 시점에 상호작용한다.
	* 질의의 각 토큰 벡터마다 문서의 모든 토큰 벡터와 유사도를 계산하고, 그중 **가장 높은 값**(Maximum Similarity, MaxSim)만 고른다.
	* 질의의 모든 토큰에 대한 MaxSim 값을 합산해 질의–문서 관련성 점수를 낸다.

이 구조 덕분에 비용이 큰 문서 인코딩을 미리 해서 저장해 둘 수 있다. 검색 시점에는 질의만 인코딩하고, 저장해 둔 문서 벡터와 MaxSim 연산만 하면 되므로 검색이 크게 빨라진다.

## A.2) 활용 방식

ColBERT 는 MS MARCO, TREC CAR 등 여러 표준 벤치마크에서 효과를 입증했다. 활용 방식은 크게 두 가지다.

### A.2.1) 검색 및 재순위화 (Retrieve-and-Rerank)

가장 일반적인 활용은 2단계 파이프라인이다.

* **1단계 (검색)**: BM25 같은 빠른 키워드 검색으로 방대한 문서 중 상위 후보(예: 1,000개)를 추린다.
* **2단계 (재순위화)**: ColBERT 가 이 후보의 문맥적 의미를 분석해 최종 순위를 다시 매긴다.
	* 기존 BERT 기반 재순위화 모델보다 **170배 이상 빠르면서** 거의 대등한 정확도를 냈다.

### A.2.2) End-to-end 검색

ColBERT 는 BM25 같은 외부 모델 없이 대규모 문서 컬렉션에서 직접 관련 문서를 찾는 end-to-end 검색도 할 수 있다. Faiss 같은 근사 최근접 이웃(ANN) 탐색으로 수많은 토큰 벡터 중 후보를 효율적으로 찾고, 그 뒤 정확한 점수를 계산한다.

### A.2.3) ColBERTv2

후속 버전인 **ColBERTv2** 는 잔차 압축(residual compression) 같은 기법을 도입했다.

* 임베딩 **저장 공간을 6–10배 줄이면서도 검색 품질은 오히려 올랐다.**

## A.3) 학습 방식

ColBERT 는 대조 학습(Contrastive Learning)으로 파인튜닝한다. 모델이 관련 있는 쌍과 관련 없는 쌍을 잘 구별하도록 학습시킨다.

### A.3.1) 학습 데이터

학습에는 **(질의 q, 긍정 문서 d+, 부정 문서 d-)** 세 개로 이루어진 트리플렛(triplet) 데이터를 쓴다.

* **질의 (Query, q)**: 사용자의 검색어
* **긍정 문서 (Positive Document, d+)**: 해당 질의와 실제로 관련 있는 문서
* **부정 문서 (Negative Document, d-)**: 해당 질의와 관련 없는 문서

### A.3.2) 학습 목표와 손실 함수

학습 목표는 **긍정 쌍의 점수는 높이고 부정 쌍의 점수는 낮추는 것**이다. 즉 Score(q, d+) 가 Score(q, d-) 보다 훨씬 높아지도록 파라미터를 업데이트한다.

논문은 **Pairwise Softmax Cross-Entropy Loss** 를 쓴다.

1. 트리플렛 (q, d+, d-) 하나가 주어지면 두 쌍의 점수를 각각 계산한다.
	* 긍정 쌍 점수: `S_pos = Score(q, d+)`
	* 부정 쌍 점수: `S_neg = Score(q, d-)`
	* 여기서 Score 함수는 **MaxSim 연산의 합**이다.
2. 두 점수를 소프트맥스(Softmax)에 통과시켜 손실(loss)을 계산한다.
	* S_pos 가 S_neg 보다 클 확률을 최대화하는 것과 같다.
	* 수식으로는 -log(exp(S_pos) / (exp(S_pos) + exp(S_neg))) 와 비슷한 형태다.
3. 손실을 역전파(backpropagation)해 BERT 인코더와 추가된 선형 계층의 가중치를 업데이트한다.

이 과정을 많은 트리플렛에 반복하면서 모델은 어떤 토큰 상호작용이 관련성을 높이는지 배운다. 즉 **MaxSim 점수를 잘 만들어 내는 토큰 임베딩을 생성하도록 학습**된다.

## A.4) BERT 기반 Bi-Encoder 와의 비교

논문 저자들은 ablation study 로 BERT 기반 Bi-Encoder 와 ColBERT 를 비교했다.

### A.4.1) Bi-Encoder

* **구조**: 질의 인코더와 문서 인코더가 따로 있다 (그래서 이름이 Bi-Encoder 다).
* **표현**: 질의와 문서를 각각 **단일 벡터(Single Vector)** 하나로 압축한다.
	* 보통 BERT 의 [CLS] 토큰 출력을 텍스트 전체를 대표하는 벡터로 쓴다.
* **점수 계산**: 두 단일 벡터의 유사도(예: 코사인 유사도, 내적)를 최종 점수로 쓴다.
	* DPR, S-BERT(검색용) 등이 대표적인 예다.

### A.4.2) 논문의 비교 결과

ColBERT 논문의 **Figure 5 (Ablation results)** 에 이 비교가 나온다.

* **비교 대상**: `BERT [CLS]-based dot-product` 모델이 전형적인 **Bi-Encoder** 다.
	* BERT 의 `[CLS]` 토큰으로 질의와 문서의 단일 벡터를 만들고, 두 벡터의 내적(dot-product)으로 점수를 계산한다.

* **결과**: 위 그래프에서 Bi-Encoder 방식인 **[A] 모델은 ColBERT([D], [E])보다 MRR@10 이 현저하게 낮다.**

### A.4.3) ColBERT 가 앞서는 이유

성능 차이는 두 모델의 구조 차이에서 나온다.

* **정보 병목 (Information Bottleneck)**: Bi-Encoder 는 질의나 문서의 정보를 **고정된 크기의 벡터 하나에 억지로 압축**해야 한다.
	* 이 과정에서 세밀하고 중요한 정보가 손실된다.
* **세밀한 상호작용 (Fine-grained Interaction)**: ColBERT 는 정보를 하나로 압축하지 않는다.
	* 모든 토큰의 벡터를 그대로 유지한 채, 검색 시점에 질의 토큰과 문서 토큰을 MaxSim 으로 비교한다.

## A.5) 토큰 개수

**질의(Query)는 고정된 개수, 문서(Document)는 가변적인 개수**의 토큰을 쓴다.

### A.5.1) 질의 (Query)

* **고정 길이 (논문 기준 32개)**: 질의는 항상 **32개 토큰**(Nq=32)으로 길이를 고정한다.
* **패딩과 잘라내기 (Padding & Truncation)**:
	* 질의 토큰이 32개보다 적으면 나머지를 BERT 의 특수 토큰 [MASK] 로 채운다(패딩).
	* 논문은 이를 **질의 증강(Query Augmentation)** 이라고 부른다. [MASK] 위치에서도 학습을 통해 질의를 확장하거나 중요한 단어에 가중치를 주는 임베딩이 생길 수 있다.
	* 질의가 32개보다 길면 32개까지만 쓰고 나머지는 잘라낸다.

### A.5.2) 문서 (Document)

* **가변 길이**: 문서는 내용이 다양하므로 길이를 고정하지 않는다.
* **일반적인 길이**: MS MARCO 같은 구절 검색(Passage Retrieval) 데이터셋의 문서는 보통 짧은 문단이다.
	* WordPiece 토큰화를 거치면 **수십 개에서 100–200개 정도의 토큰**이 되는 경우가 많다.
* **긴 문서 처리**: 위키피디아 전체 페이지처럼 긴 문서는 BERT 의 최대 입력 길이(보통 512 토큰)에 맞춰 **여러 구절(passage)로 나눈다.**
	* 나눈 구절을 각각 별도 문서로 인덱싱한다.

| 구분 | 토큰 개수 | 처리 방식 |
|---|---|---|
| **질의 (Query)** | **32개 (고정)** | 짧으면 [MASK] 로 패딩, 길면 잘라냄 |
| **문서 (Document)** | **가변적 (보통 100–200개)** | 모델의 최대 길이를 넘으면 여러 구절로 분할 |

## A.6) ColBERT 모델의 단일 벡터 검색 활용

**ColBERT 방식으로 학습한 모델을 단일 벡터 검색에 쓸 수는 있지만 성능이 매우 나쁠 가능성이 높다.** 학습 목표가 근본적으로 다르기 때문이다.

### A.6.1) 단일 벡터 검색 (Bi-Encoder 방식)의 학습

* **학습 목표**: Bi-Encoder(예: DPR, S-BERT)는 `[CLS]` 토큰 하나에 질의나 문서 전체 의미를 잘 압축하도록 학습한다.
	* 학습 과정 전체가 [CLS] 벡터를 좋은 대표 벡터로 만드는 데 집중된다.
* **손실 함수 적용**: `[CLS]` 벡터끼리의 코사인 유사도나 내적 점수로 손실을 계산하고 모델을 업데이트한다.

### A.6.2) ColBERT 의 학습

* **학습 목표**: **각 토큰 임베딩이 MaxSim 연산의 좋은 재료가 되도록** 학습한다.
	* [CLS] 토큰은 특별 대우를 받지 않고, 다른 일반 토큰과 같은 역할을 한다.
* **손실 함수 적용**: **모든 토큰**의 MaxSim 점수를 합산한 최종 점수로 손실을 계산한다.
	* 모델은 [CLS] 토큰 하나가 아니라 **모든 토큰 임베딩의 앙상블**이 좋은 점수를 내도록 학습된다.

### A.6.3) 비유

* **Bi-Encoder**: 총괄 매니저([CLS] 토큰) 한 명을 훈련한다.
	* 이 매니저가 혼자 팀 전체를 대표해 다른 팀 매니저와 소통(유사도 계산)한다.
* **ColBERT**: 팀원 전원(모든 토큰)을 각자 분야의 전문가로 훈련한다.
	* 각 전문가는 상대 팀의 특정 전문가와 소통(MaxSim 연산)하는 데 특화된다.
	* 팀 간 평가는 이 개별 소통 결과를 종합해 이루어진다.

전문가 한 명에게 총괄 매니저 일을 맡기면 제대로 해내지 못하는 것과 같다. ColBERT 로 학습한 모델의 [CLS] 토큰은 문서 전체 의미를 압축하도록 학습되지 않았으므로, 이를 단일 벡터로 쓰면 성능이 크게 떨어진다. **모델 아키텍처와 학습 목표는 긴밀하게 연결되어 있어, 하나를 바꾸면 다른 쪽도 함께 고려해야 한다.**

# B) ColBERT Research Questions (RQs)

## B.1) RQ1: 재순위(re-ranking) 설정에서 효율과 성능의 격차

> 일반적인 재순위 설정에서 ColBERT 는 고효율 모델과 고성능 신경망 모델 사이의 격차를 얼마나 해소하는가?

**ColBERT 는 기존 고성능 신경망 모델과 비슷한 효과를 내면서 훨씬 효율적이다.**

* MS MARCO 재순위 성능(MRR@10 34.9)은 당시 최고 성능 모델 BERT-large(35.9)보다 약간 낮다.
	* 다른 신경망 모델보다는 월등히 높다.
* 비용 측면에서 BERT-base 대비 처리 속도(latency)는 170배 이상 빠르고, 연산량(FLOPs)은 13,900배 적다.

## B.2) RQ2: 대규모 컬렉션에서의 end-to-end 검색

> 재순위를 넘어, ColBERT 가 대규모 문서 컬렉션에서 직접 end-to-end 검색을 효과적으로 지원하는가?

**ColBERT 는 대규모 문서 컬렉션에서 end-to-end 검색을 효과적으로 지원하고, 재순위 방식보다 성능도 높다.**

* MS MARCO 전체 880만 개 문서에서 상위 1,000개를 직접 검색하는 실험에서 MRR@10 36.0 을 기록했다.
	* BM25(16.7)나 doc2query, DeepCT 같은 다른 모델보다 훨씬 높다.
* End-to-end 검색은 초기 단계에서 관련 문서를 더 많이 찾아내므로(recall 이 높으므로) 최종 MRR@10 도 오른다.
	* 예를 들어 ColBERT 의 Recall@50 이 BM25 의 Recall@1000 보다 높다.

## B.3) RQ3: 구성 요소별 기여 (ablation)

> ColBERT 의 각 구성 요소(예: 지연 상호작용, 질의 증강)는 성능에 어떤 영향을 주는가?

**핵심 구성 요소는 모두 성능에 필수적이다.** 각 요소를 빼면 성능이 눈에 띄게 떨어진다.

* **지연 상호작용(Late Interaction)**: 단일 벡터 유사도 계산(dot-product)으로 바꾸면 성능이 크게 떨어진다 (A.4.2 의 [A] 모델).
	* 질의와 문서의 임베딩을 토큰 단위로 비교하는 세밀한 상호작용이 중요하다는 뜻이다.
* **최대 유사도(MaxSim)**: 평균 유사도로 바꿔도 성능이 떨어진다.
	* 질의의 특정 용어가 문서의 특정 부분과 강하게 연결되는 관계를 잡아내는 것이 중요하다는 뜻이다.
* **질의 증강(Query Augmentation)**: [mask] 토큰으로 질의를 확장하거나 재가중하는 기능을 빼면 MRR@10 이 현저히 낮아진다.

## B.4) RQ4: 인덱싱의 오프라인 계산·메모리 비용

> 오프라인 계산과 메모리 오버헤드 측면에서 ColBERT 의 인덱싱 비용은 어느 정도인가?

**ColBERT 의 인덱싱 비용은 실용적인 수준이고, 최적화로 속도와 메모리를 더 줄일 수 있다.**

* **인덱싱 처리량(Throughput)**: 다중 GPU 처리, 배치 최적화 등을 적용하면 MS MARCO 전체 문서를 약 3시간 만에 인덱싱한다.
	* 분당 50,000개 이상의 문서를 처리하는 속도다.
* **메모리 사용량(Footprint)**: 문서 임베딩이 차지하는 공간은 설정으로 조절할 수 있다.
	* 표준 설정(임베딩 차원 128, 차원당 4바이트)에서는 286GiB 가 필요하다.
	* 가장 공간 효율적인 설정(차원 24, 차원당 2바이트)에서는 27GiB 로 MS MARCO 전체를 표현하고, 성능 하락은 1% 에 그친다.

# C) ANN 을 활용한 End-to-end 검색

ColBERT 를 BM25 없이 end-to-end 검색에 쓸 때는 **ANN(Approximate Nearest Neighbor, 근사 최근접 이웃) 검색으로 MaxSim 연산을 효율적으로 구현**한다. MaxSim 을 ANN 으로 대체하는 것이 아니라, **ANN 으로 후보를 추려 MaxSim 을 계산할 문서 수를 크게 줄인다.**

## C.1) 오프라인 인덱싱

1. 컬렉션의 **모든 문서**(예: 880만 개)를 ColBERT 문서 인코더에 통과시킨다.
2. 각 문서는 여러 개의 작은 임베딩 묶음이 된다 (예: 문서 하나가 임베딩 100개로 표현됨).
3. 이렇게 생긴 **수억 개(880만 개 문서 x 평균 100개 임베딩) 임베딩을 모두 하나의 거대한 ANN 인덱스(예: Faiss 라이브러리)에 넣는다.**
4. ANN 인덱스의 각 임베딩은 자신이 **어느 문서에서 왔는지** 출처 정보를 갖고 있어야 한다.

## C.2) 온라인 검색

쿼리가 들어오면 두 단계로 검색한다.

### C.2.1) ANN 을 이용한 후보 필터링

1. 쿼리를 ColBERT 쿼리 인코더에 통과시켜 쿼리 임베딩 묶음(예: q1, q2, ..., q32)을 만든다.
2. **각 쿼리 임베딩(q1, q2 등)마다** ANN 인덱스에서 가장 유사한 문서 임베딩을 k'개씩(예: 1,000개) 찾는다.
	* q1 과 가장 유사한 문서 임베딩 1,000개 검색
	* q2 와 가장 유사한 문서 임베딩 1,000개 검색
	* ...
	* q32 와 가장 유사한 문서 임베딩 1,000개 검색
3. 찾은 문서 임베딩의 출처 문서를 확인하고 중복을 제거한다.
	* 수백만 개 문서 중 **몇천 개의 유력한 후보 문서** 목록이 남는다.

### C.2.2) 정확한 ColBERT 점수 계산과 재순위화

1. 수천 개로 줄어든 후보 문서에 대해서만 **원래의 ColBERT MaxSim 점수**를 계산한다.
	* 각 후보 문서마다 점수 = Sum(MaxSim(쿼리 임베딩, 문서 임베딩)) 을 정확하게 계산한다.
2. 이 점수로 최종 순위를 매겨 결과를 낸다.

## C.3) BM25 대체와 MaxSim·ANN 의 관계

* **BM25 의 역할 대체**: BM25 가 키워드 매칭으로 후보 문서를 찾던 역할을, ANN 기반 의미 유사도 검색이 맡는다.
* **MaxSim 과 ANN 의 관계**: MaxSim 은 쿼리와 문서 하나 사이의 최종 점수를 계산하는 채점 공식이다.
	* ANN 은 전체 문서를 다 채점하는 대신 **채점할 가치가 있는 문서를 빠르게 골라내는 필터** 역할을 한다.

이 2단계 접근 덕분에 ColBERT 는 키워드가 일치하지 않아도 의미적으로 관련된 문서를 초기 단계부터 찾아낼 수 있다(높은 recall). 그래서 BM25 기반 재순위 방식보다 성능이 높다.
