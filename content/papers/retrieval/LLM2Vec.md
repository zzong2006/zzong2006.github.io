# A) LLM2Vec 개요

LLM2Vec 은 GPT 같은 디코더-전용(decoder-only) 대규모 언어 모델(LLM)을, BERT 처럼 텍스트 의미를 벡터로 잘 뽑는 텍스트 인코더(text encoder)로 바꾸는 비지도 학습 방법이다. 방법은 간단하지만 효과가 크다. 논문은 생성형으로 알려진 LLM 도 약간만 조정하면 텍스트 임베딩(embedding)에서 최고 성능을 낼 수 있다고 주장한다.

## A.1) 연구 배경

* **디코더-전용 LLM 의 한계**: GPT, LLaMA, Mistral 같은 모델은 다음 단어를 예측하도록 학습된다.
	* 인과적 어텐션(causal attention)을 써서 각 토큰은 자기보다 앞에 있는 토큰만 참고한다.
	* 글을 생성하기엔 유리하지만, 문장 전체 의미를 벡터 하나로 압축하는 텍스트 임베딩에는 맞지 않는다.
* **인코더 모델의 장단점**: BERT 같은 인코더(encoder) 모델은 앞뒤 문맥을 한 번에 봐서 텍스트 임베딩에 강하다.
	* 다만 모델과 데이터를 키워도 성능 향상이 정체되는 경향(scaling law 부재)이 있어 최근 LLM 의 발전 속도를 따라가지 못한다.

LLM2Vec 은 두 모델의 장점을 결합해, LLM 의 확장성과 표현력을 텍스트 임베딩에 활용한다.

## A.2) 3단계 방법론

LLM2Vec 은 간단한 세 단계로 이뤄져 있다.

![[img-3f1d5f86b3.png]]

### A.2.1) 1단계: 양방향 어텐션 활성화 (Enabling Bidirectional Attention)

디코더-전용 모델의 가장 큰 제약인 인과적 어텐션을 해제한다. 어텐션 마스크를 수정해 모든 토큰이 문장 안의 다른 모든 토큰(미래 토큰 포함)을 참조하게 한다. 그러면 구조적으로는 BERT 같은 양방향 모델이 된다.

이 단계만으로는 부족하다. 모델이 양방향 문맥을 보도록 학습된 적이 없어서, 마스크만 바꾸면 대부분의 모델에서 오히려 성능이 크게 떨어진다.

### A.2.2) 2단계: 마스크된 다음 토큰 예측 (Masked Next Token Prediction, MNTP)

LLM2Vec 의 핵심 적응 훈련이다. 뒤만 보도록 훈련된 모델이 양방향 어텐션을 효과적으로 쓰도록 학습시킨다. 이 단계만으로도 모델은 단어 수준 의미를 풍부하게 파악하는 인코더가 된다.

* **작동 방식**: BERT 의 마스크된 언어 모델링(MLM)과 GPT 의 다음 토큰 예측을 결합했다.
	* 문장에서 일부 토큰을 무작위로 `[MASK]` 처리하고, 양쪽 문맥을 모두 써서 가려진 토큰을 예측하게 한다.
* **손실 계산 위치**: 마스크된 토큰(`i` 위치)을 예측할 때, 그 위치가 아니라 바로 **이전 토큰(`i-1` 위치)의 표현**으로 손실(loss)을 계산한다.
	* 원래 학습 방식인 다음 토큰 예측과 최대한 비슷하게 맞춰 훈련 안정성을 높인다.

예시 문장: "고양이가 `[MASK]` 위에 앉았다." (원래 단어: "매트")

`[MASK]` 위치를 `i` 라 하면 바로 앞 토큰 "가" 가 `i-1` 위치다.

* **양방향 문맥 참조**: 1단계에서 양방향 어텐션을 켰으므로, 모델은 "고양이", "가", "위에", "앉았다" 를 모두 참고한다.
	* 이 정보를 종합해 문장 안 각 토큰의 hidden representation 벡터를 계산한다.
	* GPT 라면 "고양이", "가" 만 보고 다음 단어를 예측해야 한다. 기존 GPT 와 가장 크게 다른 지점이다.
* **BERT 의 손실 계산**: `[MASK]` 토큰(`i` 위치)의 최종 표현 벡터로 "이 자리에 '매트'가 와야 한다" 를 학습한다.
* **LLM2Vec 의 손실 계산 (i-1 트릭)**: `[MASK]` 토큰의 벡터 대신 바로 앞 토큰 "가"(`i-1` 위치)의 최종 표현 벡터를 쓴다.
	* 이 벡터로 "다음 토큰은 '매트'" 를 예측하도록 학습한다.
* **i-1 위치를 쓰는 이유**: 모델은 원래 현재 토큰 정보로 다음 토큰을 예측하도록 학습됐다.
	* 비어 있는 `[MASK]` 자리의 표현으로 그 자리를 채우게 하면 기존 학습 방식과 어긋난다.
	* 그래서 "앞 토큰으로 다음 토큰 맞히기" 는 그대로 두고, 앞 토큰("가")의 표현을 만들 때 뒤쪽의 "위에", "앉았다" 까지 참고하게 한다.
	* 기존 학습 방식을 유지하면서 양방향 문맥을 자연스럽게 통합하는 절충안이다.

### A.2.3) 3단계: 비지도 대조 학습 (Unsupervised Contrastive Learning)

MNTP 가 단어 수준 표현력을 높인다면, 이 단계는 문장 전체 의미를 담는 **시퀀스(문장) 수준 임베딩**을 학습한다. SimCSE(Simple Contrastive Learning of Sentence Embeddings)를 쓴다.

비슷한 의미의 문장은 벡터 공간에서 가깝게, 다른 의미의 문장은 멀게 배치하도록 학습한다. 비지도라서 "두 문장이 유사하다" 같은 정답 라벨이 없으므로, 학습 쌍을 데이터에서 직접 만든다.

* **긍정 쌍(positive pair)**: 같은 문장을 모델에 두 번 넣되, 매번 다른 드롭아웃(dropout) 마스크를 적용해 미세하게 다른 임베딩 두 개를 만든다.
	* 예: "오늘 날씨가 정말 좋다." 를 첫 번째 통과에서 dropout 패턴 A 로 `임베딩 A`, 두 번째 통과에서 패턴 B 로 `임베딩 B` 를 얻는다.
	* dropout 은 훈련 때마다 신경망 연결 일부를 무작위로 끊는 기능으로, 원래는 과적합을 막는 용도다.
	* 두 임베딩은 같은 문장에서 나왔으므로 의미가 같아야 하고, 모델은 둘의 유사도를 높이도록 학습한다.
* **부정 쌍(negative pair)**: 같은 배치(batch) 안의 다른 문장 임베딩과 짝을 지은 쌍이다.
	* 예: 같은 배치에 "내일 회의가 있다." (`임베딩 C`), "이 식당은 음식이 맛있다." (`임베딩 D`) 가 있으면 `(임베딩 A, 임베딩 C)`, `(임베딩 A, 임베딩 D)` 가 부정 쌍이다.
	* 모델은 부정 쌍의 유사도를 낮추도록 학습한다.

# B) 주요 실험 결과

* **비지도 학습 성능**: LLaMA, Mistral 등 여러 LLM 에 적용해 MTEB(Massive Text Embedding Benchmark)에서 기존 비지도 임베딩 모델을 큰 차이로 앞서고 새 SOTA(State-of-the-art)를 달성했다.
	* Mistral-7B 와 결합했을 때 가장 좋았다.
* **지도 학습 성능**: 공개 데이터셋으로 지도 학습을 더하면, 공개 데이터만으로 학습한 모델 가운데 MTEB 최고 성능을 기록했다 (논문 Table 2, 9 참조).
* **Echo Embeddings 대비 효율성**: 같은 시기에 제안된 Echo Embeddings 는 입력을 두 번 반복해 양방향 문맥을 본다.
	* LLM2Vec 은 입력 길이를 늘리지 않아 추론 계산 효율이 더 높다.
* **Mistral-7B 의 특이점**: 다른 모델과 달리 Mistral-7B 는 MNTP 없이 1단계(양방향 어텐션 활성화)만 적용해도 성능이 크게 떨어지지 않고 오히려 올랐다.
	* 논문은 Mistral-7B 가 사전 학습의 적어도 일부에서 prefix language modeling 같은 양방향 어텐션을 썼을 수 있다고 추측한다.

# C) 학습 데이터와 학습 규모

논문은 효율성을 특히 강조한다. LLM2Vec 은 대량의 특수 데이터셋 없이, 적고 구하기 쉬운 데이터로 빠르게 학습한다. 데이터 양보다 학습 단계(step) 수가 더 중요하고, 그마저도 적은 횟수로 충분하다.

## C.1) 비지도 학습 (MNTP, SimCSE)

모델이 양방향 문맥을 이해하고(MNTP) 문장 전체 의미를 잘 요약하게(SimCSE) 만드는 단계다. 학습 규모는 70억–80억 파라미터 모델 기준이다.

| 단계 | 데이터 | 배치 크기 | step 수 | 학습 시간 (A100 1대) |
| --- | --- | --- | --- | --- |
| MNTP | Wikitext-103 (영문 위키피디아 일부를 정리한 공개 데이터셋) | 32 | 1,000 | 약 100분 |
| SimCSE | 영문 위키피디아 문장 100만 개 (공개 데이터) | 128 | 1,000 | 약 3시간 |

* **사전 학습 대비 규모**: LLM 을 처음부터 사전 학습(Pre-training)하는 데 수천억 단어와 수개월이 드는 데 비하면 극히 짧다.
	* 이미 방대한 지식을 가진 LLM 에 새 스킬을 가르치는 데는 데이터가 많이 필요 없다.

## C.2) 지도 학습 (Supervised Learning)

특정 목적(예: 검색 성능 극대화)을 위해 정답이 있는 데이터로 모델을 추가 튜닝하는 단계다.

* **사용 데이터**: 다른 연구(E5, Springer et al.)가 공개한 데이터셋으로, 약 150만 개 샘플이다.
* **학습 규모**: 배치 크기 512 로 1,000 step 만 훈련했다.
* **샘플 효율성**: 1.5M 이라는 샘플 수보다, 1,000번 업데이트만으로 최고 성능에 도달했다는 점이 중요하다.
	* 논문 Figure 6 을 보면 LLM2Vec 을 먼저 적용한 모델은 지도 학습 초반(예: 100–200 step)부터 성능이 빠르게 오른다.
	* 이를 sample-efficiency(샘플 효율성)가 높다고 표현한다.

## C.3) 적은 데이터로 충분한 이유

1. **적은 훈련 단계(Few Steps)**: 가중치 업데이트 1,000번만으로 모델을 효과적으로 변환한다.
2. **접근성 높은 데이터(Accessible Data)**: 위키피디아 같은 비정형 텍스트만으로 충분히 학습하고, 비싼 레이블 데이터가 필요 없다.
3. **파라미터 효율적 튜닝(Parameter-Efficient Tuning)**: **LoRA** 로 수십억 개 파라미터 대부분은 그대로 두고 아주 작은 일부만 학습한다.
	* 적은 GPU 메모리와 시간으로 튜닝할 수 있다.
	* 논문 원문: "We merge the MNTP LoRA weights into the base model and initialize new LoRA parameters before starting the SimCSE training, which ensures that the models retains the knowledge learned in the previous step."
4. **새 지식 학습이 아님**: LLM2Vec 은 모델에 새 지식(예: '셰익스피어는 작가다')을 가르치지 않는다.
	* 모델이 이미 아는 지식을 양방향 문맥으로 표현하고 요약하는 방법만 가르치므로 적은 훈련으로 충분하다.
