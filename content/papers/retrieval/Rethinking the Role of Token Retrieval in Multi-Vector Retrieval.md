Google DeepMind 연구진의 논문으로, multi-vector 검색에서 토큰 검색(token retrieval)의 역할을 다시 정의한 모델 XTR(ConteXtualized Token Retriever)을 제안한다.

# A) 기존 multi-vector 검색의 한계

ColBERT 같은 기존 multi-vector 검색 모델은 질의(query)와 문서의 토큰 간 상호작용을 계산해 높은 정확도를 낸다. 하지만 추론이 복잡하고 느린 3단계(토큰 검색 → 정보 수집 → 점수 계산)로 이루어져 있다.

* **정보 수집(gathering) 단계의 비용**: 후보 문서의 **모든** 토큰 벡터를 불러와야 해서 계산 비용과 시간이 크다.
	* 그래서 대규모 서비스에 적용하기 어렵다.
* **학습과 추론의 불일치**: 학습은 주로 마지막 점수 계산 단계에 맞춰져 있다.
	* 후보를 결정하는 첫 토큰 검색 단계는 최적화되지 않는다.

# B) XTR 의 접근

## B.1) 핵심 아이디어

XTR 은 토큰 검색 단계의 역할을 다시 정의해 이 문제를 푼다.

* **2단계 프로세스**: 가장 중요한 문서 토큰을 먼저 검색하도록 모델을 학습시킨다.
	* 이렇게 고른 토큰만으로 정확한 점수 계산이 가능하다.
	* 그래서 비용이 큰 정보 수집 단계를 없애고 검색 과정을 단순화한다.
* **새로운 학습 목표**: 학습 중에 토큰 검색 단계를 시뮬레이션하는 목적 함수를 도입했다.
	* 학습 목표와 실제 추론 과정 사이의 불일치를 없애고 토큰 검색 성능을 끌어올린다.
* **점수 계산 비용 절감**: 후보 문서 순위를 매기는 점수 계산(scoring) 단계의 연산량(FLOPs)을 ColBERT 대비 4,000배 이상 줄였다.
	* 검색된 토큰 정보만 쓰기 때문에 가능하다.

## B.2) ColBERT 와의 관계

**XTR 은 ColBERT 를 그대로 다시 학습시킨 모델이 아니다.** ColBERT 같은 multi-vector 아키텍처를 쓰되, **학습 방법을 근본적으로 바꿨다.** 핵심 연산은 MaxSim 을 변형해 쓴다.

* **ColBERT 의 문제점**: 학습 시 (미니배치 안의) 정답 문서와 오답 문서의 최종 점수 차이를 벌리는 데만 집중한다.
	* 이 최종 점수는 문서의 **모든 토큰**에 MaxSim 연산을 한 결과다.
	* 실제 추론에서는 비용 때문에 모든 문서의 모든 토큰을 볼 수 없고, 1단계 토큰 검색으로 후보 문서를 추린다.
	* 즉 **학습 방식(최종 점수 최적화)과 실제 사용 방식(토큰 검색이 중요) 사이에 괴리**가 있다.
* **XTR 의 접근법**: 학습 과정 안에서 토큰 검색 단계를 흉내 낸다.
	* 모델이 최종 점수만 잘 내는 것이 아니라, **처음부터 올바른 토큰을 잘 검색하도록 직접 학습**시킨다.

## B.3) In-Batch Token Retrieval 학습

XTR 의 학습 방식을 In-Batch Token Retrieval 이라고 부른다. MaxSim 연산의 적용 범위가 ColBERT 와 다르다.

### B.3.1) ColBERT 의 학습: 문서 단위 경쟁

1. 쿼리(Query) 하나가 주어진다.
2. 미니배치(mini-batch) 안에 정답 문서 D+ 와 여러 오답 문서 D- 가 있다.
3. 각 문서(D+, D-)마다 **독립적으로** MaxSim 점수를 계산한다.
	* `f_colbert(Q, D) = Σ (각 쿼리 토큰과 D 문서 내 가장 유사한 토큰 간의 유사도)`
4. 이 점수로 D+ 의 점수는 높이고 D- 의 점수는 낮추도록 학습한다.
	* **문제**: 오답 문서 D- 안에 쿼리 토큰과 아주 비슷한 토큰이 하나만 있어도, 1단계 토큰 검색에서 이 오답 문서가 상위에 오를 수 있다.
	* 하지만 학습 시에는 문서 전체 점수가 낮으므로 이 문제가 드러나지 않는다.

### B.3.2) XTR 의 학습: 토큰 단위 경쟁

1. 쿼리(Query) 하나가 주어진다.
2. 미니배치 안의 **모든 문서(D+, D-)의 모든 토큰**을 한곳에 모아 큰 토큰 풀(pool)을 만든다.
3. 쿼리의 각 토큰(`q_i`)마다 **토큰 풀 전체에서** 가장 유사한 상위 `k`개(`ktrain`)의 문서 토큰을 찾는다.
	* 학습 중에 토큰 검색을 시뮬레이션하는 과정이다.
4. 특정 문서 `D` 의 점수를 계산할 때 `D` 안의 모든 토큰을 보지 않는다.
	* **3번에서 상위 `k`개 안에 든 `D` 소속 토큰만** 대상으로 MaxSim 점수를 계산한다.
5. 정답 문서 D+ 의 토큰이 하나도 3번의 상위 `k`개에 들지 못하면 D+ 의 점수는 0 이 된다.
	* 이는 큰 손실(loss)로 이어진다.
	* 그래서 모델은 정답 문서의 토큰이 이 경쟁에서 이기도록 토큰 임베딩을 만드는 방향으로 학습된다.

## B.4) 두 MaxSim 의 비교

* **ColBERT 의 MaxSim**: 쿼리 토큰이 각 문서 안에서 자신과 가장 닮은 토큰을 찾는다.
	* 문서 하나 안에서만 탐색한다.
* **XTR 의 MaxSim**: 쿼리 토큰이 미니배치 전체에서 자신과 가장 닮은 토큰 `k`개를 먼저 뽑는다.
	* 그다음 그중 이 문서에 속한 토큰만 본다.

이 In-batch 경쟁으로 XTR 은 최종 문서 점수뿐 아니라 **토큰 검색 단계 자체의 recall 을 크게 높였다.** 그 결과 비용이 큰 정보 수집(gathering) 단계를 생략하고도 더 빠르고 정확하게 검색한다.

# C) 주요 성과

* **BEIR**: 별도의 증류(distillation) 없이 기존 최고 성능(SOTA)을 nDCG@10 기준 2.8 앞섰다.
* **기타 벤치마크**: LoTTE, EntityQuestions, 18개 언어를 포함한 다국어 검색 벤치마크 MIRACL 에서도 좋은 성능을 냈다.
* **골든 토큰 검색**: ColBERT 보다 실제 정답 문서에 포함된 골든 토큰(gold tokens)을 훨씬 잘 찾아낸다.
	* 단어의 표면적 일치보다 문맥적 연관성을 더 잘 파악한다는 뜻이다.
