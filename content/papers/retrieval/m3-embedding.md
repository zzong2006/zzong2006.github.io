# A) M3-Embedding 핵심 요약

M3-Embedding 은 텍스트 임베딩 모델이다. 'M3' 는 이 모델의 세 가지 핵심 특징인 **다중 언어성(Multi-Linguality), 다중 기능성(Multi-Functionality), 다중 입자성(Multi-Granularity)** 을 뜻한다. 기존 임베딩 모델이 특정 언어(주로 영어), 단일 검색 기능, 짧은 텍스트에만 특화된 한계를 극복하려 한다.

## A.1) 세 가지 핵심 특징 (The "M3")

1. **다중 언어성 (Multi-Linguality)**: 100개가 넘는 언어의 의미 검색을 지원한다.
	* 같은 언어 안의 검색(multilingual retrieval)과, 한 언어로 질의해 다른 언어 문서를 찾는 교차 언어 검색(cross-lingual retrieval)이 모두 된다.
2. **다중 기능성 (Multi-Functionality)**: 모델 하나로 정보 검색(IR)에서 널리 쓰는 세 가지 검색 방식을 모두 수행한다.
	* **Dense Retrieval**: 문장 전체 의미를 벡터 하나(주로 `[CLS]` 토큰)로 압축해 빠르게 검색한다.
	* **Sparse Retrieval (Lexical Retrieval)**: 토큰마다 중요도 가중치를 학습해 키워드 매칭으로 검색하며, BM25 와 비슷하지만 가중치를 학습한다는 점이 다르다.
	* **Multi-Vector Retrieval**: 쿼리와 문서의 모든 토큰 벡터로 late interaction(지연 상호작용) 방식의 정교한 관련도 점수를 계산하며, ColBERT 와 비슷하다.
	* 세 방식을 결합한 **하이브리드 검색** (Hybrid Retrieval)으로 각 방식의 장점을 모두 살려 검색 성능을 극대화한다.
3. **다중 입자성 (Multi-Granularity)**: 짧은 문장부터 최대 8,192 토큰의 긴 문서까지 다양한 길이의 입력을 처리한다.
	* 긴 문서 검색에서 특히 강하다.

## A.2) 핵심 기술: 자기 지식 증류 (Self-Knowledge Distillation)

Dense, Sparse, Multi-vector 세 기능을 함께 학습시키려고 **자기 지식 증류** (Self-Knowledge Distillation)라는 학습 프레임워크를 제안한다.

* **교사 신호 생성**: 각 검색 방식의 관련도 점수를 합쳐 더 정확한 교사(teacher) 신호를 만든다.
* **학생 재학습**: 이 통합 신호로 각 검색 방식(학생, student)을 다시 학습시킨다.
* **상호 보완**: 각 기능이 서로의 학습을 방해하지 않고 보완해 전체 임베딩 품질이 오른다.

# B) ColBERT 대비 M3-Embedding 의 장점

[[ColBERT]] 는 다중 벡터 검색(Multi-Vector Retrieval)을 개척한 모델이다. M3-Embedding 은 ColBERT 의 핵심 아이디어인 late interaction 을 받아들이면서, 모델 하나로 속도·정확도·언어·문서 길이에 대한 다양한 요구에 대응한다.

## B.1) 통합된 다기능성 (All-in-One)

* **ColBERT**: 다중 벡터 방식 하나만 제공한다.
	* Dense·Sparse 검색까지 함께 쓰려면 BM25 나 Dense Retriever 같은 별도 모델을 붙여 파이프라인을 구성해야 한다.
* **M3-Embedding**: 1단계 검색용 Dense·Sparse Retriever 와 2단계 리랭킹에 쓸 수 있는 Multi-vector Retriever(ColBERT 방식)를 모델 하나에 모두 내장한다.
	* 빠른 Dense 검색만 쓰거나, 최고 성능을 위해 모두 결합한 하이브리드 검색을 고를 수 있다.
	* 시스템 구성이 단순해지고 모델 하나만 관리하면 되므로 운영이 편하다.

## B.2) 다중 언어·교차 언어 지원

* **ColBERT**: 기본적으로 영어에 맞춰 개발됐고, 다중 언어 버전이 있지만 M3-Embedding 만큼 포괄적이지 않다.
* **M3-Embedding**: 설계 단계부터 100개 이상 언어의 대규모 다국어 데이터로 사전 학습했다.
	* MIRACL, MKQA 벤치마크에서 영어 외 언어, 특히 low-resource language 에서도 기존 모델보다 월등히 높은 성능을 보였다.

## B.3) 긴 문서 처리 (최대 8,192 토큰)

* **ColBERT**: 처리할 수 있는 길이가 보통 512 토큰 정도로 제한된다.
	* 긴 문서는 여러 조각으로 나눠 처리해야 하고, 이 과정에서 문맥 정보를 잃을 수 있다.
* **M3-Embedding**: 최대 **8,192 토큰** 입력을 직접 처리하도록 설계됐다.
	* 법률 문서, 연구 논문, 긴 기사처럼 원문에서 바로 정보를 찾아야 하는 분야에서 ColBERT 보다 크게 유리하다.

## B.4) 공동 학습의 시너지

* **ColBERT**: 다른 모델과 파이프라인으로 연결하므로 각 모델을 따로 학습한다.
* **M3-Embedding**: 세 검색 기능을 자기 지식 증류로 함께 학습한다(joint training).
	* 한 기능의 장점이 다른 기능의 단점을 보완해, 각 모델을 따로 학습해 합칠 때보다 검색 성능이 높다.
	* 논문 실험에서 세 기능을 모두 쓴 경우(All)가 가장 좋았다.

# C) M3-Embedding 의 임베딩 생성 과정

M3-Embedding 은 입력 문장 하나로 세 가지 임베딩을 한 번에 계산한다. 사용자는 검색 목적에 따라 하나를 고르거나 조합해(하이브리드 검색) 쓴다. 예시 입력은 "AI가 세상을 어떻게 바꿀까?" 다.

## C.1) 토큰화 (Tokenization)

자연어 문장은 그대로 처리할 수 없어서 모델이 다룰 수 있는 숫자로 바꾼다.

* **입력**: "AI가 세상을 어떻게 바꿀까?"
* **토큰 분할**: 문장을 토큰으로 쪼갠다.
	* 예: `[CLS]`, `AI`, `가`, `세상`, `을`, `어떻게`, `바꿀까`, `?`, `[SEP]`
* **`[CLS]` 토큰**: 문장 전체 의미를 대표하도록 맨 앞에 붙이는 특수 토큰이다.
* **ID 변환**: 각 토큰을 모델이 미리 학습한 사전(vocabulary)의 고유 번호(ID)로 바꾼다.
	* 결과 예: `[101, 9924, 1199, 1294, ... , 102]`

## C.2) 인코더 통과

토큰 ID 배열은 **XLM-RoBERTa** 기반 Transformer 인코더로 들어간다. M3-Embedding 의 본체다.

* **문맥 파악**: 입력된 모든 토큰의 문맥적 의미를 계산한다.
	* 예를 들어 '세상' 이 'AI' 나 '바꾸다' 와 어떤 관계인지 계산한다.
* **토큰별 벡터**: 토큰마다 문맥 의미를 담은 고차원 벡터(1024차원)를 만든다.
	* 이 벡터를 마지막 은닉 상태(last hidden state)라고 부른다.
* **결과**: 입력 토큰 수만큼의 벡터 묶음(행렬)이 나온다.
	* `H_CLS` (`[CLS]` 토큰의 벡터), `H_AI` (`AI` 토큰의 벡터), `H_가` (`가` 토큰의 벡터) 등 모든 토큰의 벡터가 나온다.

이 토큰별 벡터 묶음이 세 가지 임베딩의 공통 입력이다.

## C.3) 세 가지 임베딩 생성

### C.3.1) Dense 임베딩 (빠른 범용 검색용)

* **만드는 방법**: `H_CLS` 벡터 하나만 가져와 정규화(normalize, 크기를 1로 맞춤)한다.
* **결과물**: 문장 전체 의미를 압축한 벡터 하나.
* **용도**: 문장 간 전반적인 의미 유사도를 빠르게 계산한다.
	* 예: "인공지능이 세상을 바꾸는 방법" 과 의미가 얼마나 비슷한가.

### C.3.2) Sparse 임베딩 (키워드 검색용)

* **만드는 방법**: `H_CLS` 를 뺀 토큰 벡터(`H_AI`, `H_가`, `H_세상` ...)를 각각 작은 신경망(`W_lex`)에 통과시켜 숫자 하나(중요도 가중치)로 바꾼다.
	* 이 가중치가 각 토큰이 검색에서 얼마나 중요한지 나타낸다.
* **결과물**: (토큰, 가중치) 쌍 리스트.
	* 예: `{'AI': 0.9, '세상': 0.8, '바꿀까': 0.7 ...}`
* **용도**: 특정 키워드의 중요도를 반영해 검색한다.
	* 전통적인 키워드 검색(BM25)에 가중치 학습을 더한 형태다.

### C.3.3) Multi-Vector 임베딩 (정밀 검색용, ColBERT 방식)

* **만드는 방법**: `H_CLS` 를 뺀 모든 토큰 벡터를 선형 변환(`W_mul`)한 뒤 정규화한다.
* **결과물**: 문장을 대표하는 벡터 묶음(set of vectors).
* **용도**: 쿼리의 모든 토큰 벡터와 문서의 모든 토큰 벡터를 하나씩 비교해 정교한 관련도 점수를 계산한다.
	* ColBERT 의 핵심 방식으로, 느리지만 정확도가 매우 높다.

## C.4) 세 가지 임베딩 비교

| 임베딩 종류 | 만드는 방법 | 결과물 형태 | 목적 및 장점 |
| :--- | :--- | :--- | :--- |
| **Dense** | `[CLS]` 토큰의 벡터 하나만 사용 | **단일 벡터** | 빠르고 범용적인 의미 검색 |
| **Sparse** | 각 토큰 벡터를 '중요도' 숫자로 변환 | **(토큰, 가중치) 쌍 리스트** | 키워드 중요도 기반 검색 |
| **Multi-Vector** | 모든 토큰 벡터 묶음을 변환해 사용 | **여러 벡터의 묶음(Set)** | ColBERT처럼 정교하고 정확한 순위 재조정 |
