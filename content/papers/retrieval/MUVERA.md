최신 정보 검색(IR)에서는 embedding model 이 핵심 기술로 자리 잡았다. 사용자가 “에베레스트 산의 높이는?” 같은 질의를 입력하면, IR 은 수십억 개의 문서·이미지·동영상 가운데 그 질의와 관련 있는 정보를 찾아야 한다. 임베딩 모델은 각 데이터 포인트를 벡터(임베딩) 하나로 바꿔, 의미가 비슷한 데이터가 수학적으로도 비슷한 벡터가 되게 한다. 임베딩끼리는 주로 [[dot product|inner product]](내적 유사도)로 비교하고, 효율적인 [[maximum inner product search]](MIPS) 알고리즘으로 빠르게 검색한다.

[[ColBERT]] 같은 멀티-벡터 모델이 나오면서 IR 성능이 크게 올랐다. 멀티-벡터 모델은 단일 벡터 임베딩과 달리 데이터 포인트 하나를 벡터 집합으로 표현하고, 더 정교한 유사도 함수로 데이터 간 복잡한 관계를 포착한다. 최신 멀티-벡터 모델에서 널리 쓰는 [[Chamfer distance]]는 한쪽 멀티-벡터 임베딩의 정보가 다른 쪽에 얼마나 들어 있는지 측정한다.

멀티-벡터 방식은 정확도를 크게 높이지만 계산 비용이 매우 크다. 임베딩을 여러 개 만들어야 하고 유사도 연산도 복잡해서 검색이 훨씬 비싸진다.

“[MUVERA: Multi-Vector Retrieval via Fixed Dimensional Encodings](https://arxiv.org/abs/2405.19504)”는 멀티-벡터 검색을 단일 벡터 MIPS 문제로 환원하는 알고리즘 MUVERA 를 제안한다. 쿼리와 문서의 멀티-벡터 집합을 고정 차원의 단일 벡터(Fixed Dimensional Encoding; FDE)로 바꾸고, FDE 간 내적이 원래 멀티-벡터 유사도를 근사하게 만든다. 덕분에 고속 MIPS 로 후보를 빠르게 뽑은 뒤 Chamfer 유사도로 재정렬해 효율성과 정확도를 함께 얻는다.

FDE 생성 알고리즘은 [GitHub](https://github.com/google/graph-mining/tree/main/sketching/point_cloud)에 오픈소스로 공개돼 있다.

# A) 멀티-벡터 검색의 어려움

멀티-벡터 모델은 보통 토큰마다 임베딩을 만들고, 쿼리와 문서의 유사도는 Chamfer 매칭으로 구한다. 쿼리 임베딩마다 가장 가까운 문서 임베딩과의 최대 유사도를 구해 모두 더한다. 이렇게 하면 쿼리의 각 부분이 문서의 어느 부분과 관련되는지까지 점수에 반영된다.

이 방식에는 다음 문제가 있다.

- **임베딩 수 증가**: 토큰마다 임베딩을 만들어 처리할 벡터 수가 폭증한다.
- **무거운 유사도 계산**: Chamfer 매칭은 행렬곱 기반 비선형 연산이라 단순 내적보다 훨씬 무겁다.
- **sublinear 검색 기법 부재**: 단일 벡터 검색은 공간 분할 같은 고속 MIPS 기법으로 sublinear 시간에 정확히 비교하지만, 멀티-벡터에는 이 기법을 적용할 수 없다.
	- 전통적인 MIPS 만으로는 문서 전체 내용을 반영하지 못한다.
	- 문서의 일부 토큰만 일치하고 전체적으로는 관련이 적은 경우가 그 예다.

# B) MUVERA 검색 절차

MUVERA 는 멀티-벡터 집합 전체를 고정 차원 벡터(FDE) 하나로 압축한다. 다루기 어려운 멀티-벡터 집합 대신 빠르게 비교할 수 있는 FDE 를 쓰고, FDE 끼리 비교한 값이 원래 Chamfer 유사도와 거의 같게 나오도록 설계한다.

1. **FDE 생성**: 쿼리와 문서 각각의 멀티-벡터 집합을 고정 길이 벡터 FDE 로 변환한다.
2. **MIPS 기반 1차 후보 추출**: 문서 FDE 를 표준 MIPS 인덱스에 저장해 두고, 쿼리 FDE 와의 내적으로 상위 후보를 빠르게 찾는다.
3. **재정렬(Re-ranking)**: 뽑힌 후보를 원래 Chamfer 유사도로 다시 채점해 최종 순위를 정한다.

FDE 에는 다음 성질이 있다.

- **데이터 독립적 변환**: FDE 변환은 특정 데이터셋 특성에 의존하지 않아 스트리밍 환경이나 데이터 분포 변화에도 강하다.
- **근사 보장**: 기존 단일 벡터 휴리스틱과 달리, FDE 는 지정한 오차 범위 안에서 Chamfer 유사도를 근사한다는 이론적 보장이 있다.

## B.1) 이론적 배경

MUVERA 는 probabilistic tree embeddings 등 기하 알고리즘 이론에서 착안했고, 이를 inner product 와 Chamfer similarity 상황에 맞게 확장했다.

FDE 는 임베딩 공간을 여러 영역으로 나누고, 같은 영역에 들어간 쿼리·문서 벡터끼리 근접성을 평가한다. 어떤 쌍이 가장 잘 맞을지 미리 알 수 없으므로 무작위 분할로 전체를 근사한다.

논문([paper](https://arxiv.org/abs/2405.19504))은 이렇게 얻은 FDE 내적이 Chamfer similarity 를 근사한다는 보장을 증명한다.

$$
\mathrm{Chamfer}(Q,D)\approx \langle \mathrm{FDE}(Q),\mathrm{FDE}(D)\rangle
$$

따라서 multi-vector 검색을 single-vector 프록시만으로 신뢰성 있게 처리할 수 있다.

# C) FDE (Fixed Dimensional Encodings) 생성 방법

FDE 는 다중 벡터 묶음 Q, P 사이의 Chamfer Similarity 를 단일 벡터 q, p 의 내적(inner product)으로 근사하도록 설계됐다. 생성 과정은 다음과 같다.

1. **공간 분할 (Space Partitioning)**: 벡터 공간을 여러 구역(클러스터)으로 나눈다.
	- Locality Sensitive Hashing(LSH)의 일종인 SimHash 등으로 무작위 초평면(hyperplane)을 그어 공간을 자른다.
	- 비슷한 벡터가 같은 구역에 묶일 확률이 높아진다.
2. **클러스터별 벡터 집계 (Vector Aggregation per Cluster)**: 구역마다 속한 벡터를 대표 벡터 하나로 합친다.
	- **쿼리 벡터(Q)**: 구역에 속한 쿼리 벡터를 모두 더한다(summation).
	- **문서 벡터(P)**: 구역에 속한 문서 벡터의 중심점(centroid, 평균 벡터)을 구한다.
	- 쿼리는 합, 문서는 평균으로 다르게 집계해 Chamfer 유사도의 비대칭성을 반영한다.
3. **벡터 결합 (Concatenation)**: 구역별 대표 벡터를 순서대로 이어 붙여 고정 차원의 긴 단일 벡터, 즉 FDE 를 만든다.
	- 구역마다 FDE 안의 블록 좌표가 하나씩 정해져 있다.
4. **정확도 향상 기법**
	- **반복 (Repetitions)**: 서로 다른 공간 분할로 FDE 를 여러 번 만들어 이어 붙여 결과의 안정성과 정확도를 높인다.
	- **내부 프로젝션 (Inner Projections)**: 구역별 벡터 차원을 랜덤 프로젝션으로 줄여 최종 FDE 차원이 커지는 것을 억제한다.

## C.1) 사분면 분할 예시

공간을 여러 구역으로 나누고, 구역마다 쿼리와 문서의 대표 벡터를 하나씩 만들어 이어 붙인다. 입력은 2차원(d=2) 벡터다.

| 벡터 | 소속 | 좌표 | 비고 |
| --- | --- | --- | --- |
| q1 | 쿼리 Q | (2, 8) | |
| q2 | 쿼리 Q | (-3, 4) | |
| p1 | 문서 P | (3, 7) | q1 과 매우 유사 |
| p2 | 문서 P | (6, 2) | |
| p3 | 문서 P | (-2, 5) | q2 와 매우 유사 |

### C.1.1) 공간 분할

가장 단순하게 벡터 공간을 4개 사분면으로 나눈다. 논문은 SimHash 를 쓰지만 개념을 보이려고 사분면을 쓴다.

| 구역 | 조건 | 속한 벡터 |
| --- | --- | --- |
| Zone 1 (1사분면) | x > 0, y > 0 | q1, p1, p2 |
| Zone 2 (2사분면) | x < 0, y > 0 | q2, p3 |
| Zone 3 (3사분면) | x < 0, y < 0 | 없음 |
| Zone 4 (4사분면) | x > 0, y < 0 | 없음 |

### C.1.2) 구역별 벡터 집계

구역마다 쿼리와 문서의 대표 벡터를 계산한다. 쿼리는 더하고(summation) 문서는 평균을 낸다(centroid). 이 비대칭 집계가 MUVERA 설계의 핵심이다.

- **Zone 1**: 쿼리 {q1}, 문서 {p1, p2}
	- Q_zone1 = q1 = (2, 8) (더할 벡터가 하나뿐이다)
	- P_zone1 = (p1 + p2) / 2 = ((3, 7) + (6, 2)) / 2 = (9, 9) / 2 = (4.5, 4.5)
- **Zone 2**: 쿼리 {q2}, 문서 {p3}
	- Q_zone2 = q2 = (-3, 4)
	- P_zone2 = p3 / 1 = (-2, 5)
- **Zone 3, 4**: 속한 벡터가 없어 대표 벡터는 모두 0 벡터다.
	- Q_zone3 = P_zone3 = Q_zone4 = P_zone4 = (0, 0)

### C.1.3) 벡터 결합

구역별 대표 벡터를 순서대로 이어 붙여 FDE 를 만든다.

- **FDE_Query (fq)** = [Q_zone1, Q_zone2, Q_zone3, Q_zone4] = [(2, 8), (-3, 4), (0, 0), (0, 0)] = (2, 8, -3, 4, 0, 0, 0, 0), 8차원
- **FDE_Document (fp)** = [P_zone1, P_zone2, P_zone3, P_zone4] = [(4.5, 4.5), (-2, 5), (0, 0), (0, 0)] = (4.5, 4.5, -2, 5, 0, 0, 0, 0), 8차원

### C.1.4) FDE 내적의 의미

두 FDE 의 내적(dot product)은 구역별 내적의 합이다.

fq · fp = (Q_zone1 · P_zone1) + (Q_zone2 · P_zone2) + (Q_zone3 · P_zone3) + (Q_zone4 · P_zone4)

- **Zone 1**: (2, 8) · (4.5, 4.5) = 2 × 4.5 + 8 × 4.5 = 9 + 36 = 45
- **Zone 2**: (-3, 4) · (-2, 5) = (-3) × (-2) + 4 × 5 = 6 + 20 = 26
- **Zone 3, 4**: 0
- **최종 내적값**: 45 + 26 + 0 + 0 = 71

이 계산에서 다음을 알 수 있다.

- **같은 구역에 있어야 점수를 얻는다**: q1 과 p3 는 다른 구역이라 내적에서 서로 영향을 주지 않는다.
	- 쿼리 토큰과 멀리 떨어진 문서 토큰의 상호작용을 무시하는 Chamfer Similarity 의 특성을 흉내 낸다.
- **유사한 벡터가 같은 구역에 모이면 점수가 오른다**: q1 과 p1 이 Zone 1 에, q2 와 p3 가 Zone 2 에 모여 각 구역의 내적값이 높게 나왔다.
	- FDE 내적이 Chamfer Similarity 를 근사하는 원리가 이것이다.
- **문서 벡터를 평균 내는 이유**: Zone 1 에는 p1 외에 관련 없는 p2 도 있는데, 평균을 내면 p1 의 영향력이 어느 정도 희석된다.
	- 한두 토큰만 일치하고 나머지는 관련 없는 문서의 점수가 과도하게 높아지지 않는다.

실제 논문은 더 높은 차원(d=128), 더 많은 구역(예: 64개), 서로 다른 공간 분할의 반복(Reps=20)으로 훨씬 길고 정교한 FDE 를 만든다.

## C.2) SimHash 적용 예시

### C.2.1) SimHash 개요

SimHash(유사도 해시)는 고차원 벡터의 fingerprint(지문)를 만드는 기법이다. 핵심 성질은 다음과 같다.

> 원래 공간에서 서로 가까운(유사한) 벡터는 fingerprint(해시값)도 서로 비슷할 확률이 높다.

fingerprint 가 비슷하다는 말은 0과 1 문자열에서 몇 글자만 다르다는 뜻이다. 예를 들어 10110 과 10010 은 한 글자만 다르다.

SimHash 는 공간을 무작위로 가로지르는 초평면(hyperplane) 여러 개로 fingerprint 를 만든다.

1. **초평면 생성**: 공간에 무작위 초평면(2차원에서는 직선) 여러 개를 긋는다. 초평면 하나는 공간을 두 영역으로 나눈다.
2. **방향 판정**: 각 벡터가 초평면의 어느 쪽에 있는지 본다. 한쪽이면 1, 반대쪽이면 0 이다.
3. **비트 결합**: 초평면별 0/1 을 모으면 그 벡터의 fingerprint, 즉 SimHash 값이 된다.

초평면이 2개면 각 벡터는 (첫째 초평면 결과, 둘째 초평면 결과) 형태의 2비트 fingerprint 를 갖는다. 앞의 사분면 대신 초평면 2개를 쓰는 SimHash 를 적용해 본다. 논문은 $k_{sim}$=3–6 으로 8–64개 구역을 만든다.

### C.2.2) SimHash 공간 분할

초평면은 원점을 지나며 법선 벡터(normal vector) r 로 정의한다. 벡터 `v` 와 `r` 의 내적 `(v · r)` 이 양수면 1, 음수면 0 이다.

- **초평면 1**: r1 = (1, 1)
- **초평면 2**: r2 = (-1, 2)

모든 벡터의 fingerprint 는 (r1 결과, r2 결과)이고, 이 값이 곧 Zone ID 다.

| 벡터 | v · r1 | v · r2 | Zone ID |
| --- | --- | --- | --- |
| q1 = (2, 8) | 2 × 1 + 8 × 1 = 10 → 1 | 2 × (-1) + 8 × 2 = 14 → 1 | 11 |
| q2 = (-3, 4) | (-3) × 1 + 4 × 1 = 1 → 1 | (-3) × (-1) + 4 × 2 = 11 → 1 | 11 |
| p1 = (3, 7) | 3 × 1 + 7 × 1 = 10 → 1 | 3 × (-1) + 7 × 2 = 11 → 1 | 11 |
| p2 = (6, 2) | 6 × 1 + 2 × 1 = 8 → 1 | 6 × (-1) + 2 × 2 = -2 → 0 | 10 |
| p3 = (-2, 5) | (-2) × 1 + 5 × 1 = 3 → 1 | (-2) × (-1) + 5 × 2 = 12 → 1 | 11 |

구역 할당 결과는 다음과 같다.

- **Zone 11**: q1, q2, p1, p3
- **Zone 10**: p2
- **Zone 01, 00**: 없음

사분면으로 나눴을 때와 결과가 다르다. SimHash 는 축과 무관하게 공간을 나누므로 유사한 벡터를 더 유연하게 묶는다.

### C.2.3) 구역별 벡터 집계

- **Zone 11**
	- 쿼리 {q1, q2} → Q_zone11 = q1 + q2 = (2, 8) + (-3, 4) = (-1, 12)
	- 문서 {p1, p3} → P_zone11 = (p1 + p3) / 2 = ((3, 7) + (-2, 5)) / 2 = (0.5, 6)
- **Zone 10**
	- 쿼리 없음 → Q_zone10 = (0, 0)
	- 문서 {p2} → P_zone10 = p2 = (6, 2)
- **Zone 01, 00**: 벡터가 없어 모두 (0, 0) 이다.

### C.2.4) 최종 FDE

구역 순서(11, 10, 01, 00)대로 대표 벡터를 이어 붙인다.

- **FDE_Query (fq)** = `[(-1, 12), (0, 0), (0, 0), (0, 0)]` = `(-1, 12, 0, 0, 0, 0, 0, 0)`
- **FDE_Document (fp)** = `[(0.5, 6), (6, 2), (0, 0), (0, 0)]` = `(0.5, 6, 6, 2, 0, 0, 0, 0)`

두 FDE 를 내적하면 q1, q2 와 p1, p3 는 Zone 11 에서 상호작용한다. p2 는 Zone 10 에 혼자 남고, 그 구역의 쿼리 대표 벡터가 0 이라 점수에 기여하지 못한다. 내적값은 (-1) × 0.5 + 12 × 6 = 71.5 다.

- 같은 recall 을 얻는 데 필요한 candidate 수가 5–20배 적다.

## D.2) latency 감소

최신 multi-vector 검색 시스템인 PLAID 와 비교해, MUVERA 는 BEIR 데이터셋 전반에서 평균 recall 이 10% 높고 latency 는 약 90% 짧다.

## D.3) 메모리 압축

MUVERA 의 FDE 는 product quantization 등 압축 기법으로 메모리를 최대 32배 줄여도 품질 저하 없이 쓸 수 있다.

# E) Related Work

논문은 MUVERA 를 기존 다중 벡터 검색 방법과 비교한다.

- **ColBERT / ColBERTv2**: 다중 벡터 표현과 late-interaction 개념을 도입한 선구적 모델이다.
	- 각 쿼리 토큰 벡터와 가장 유사한 문서 토큰 벡터의 유사도를 합산한다.
	- MUVERA 실험은 ColBERTv2 가 만든 임베딩을 쓴다.
- **SV Heuristic (단일 벡터 휴리스틱)**: 가장 기본적인 다중 벡터 검색 방식으로, ColBERT 초기 버전과 PLAID 의 기반이다.
	- 쿼리 벡터마다 가장 유사한 문서 토큰을 MIPS 로 따로 찾고, 후보 문서를 모아 다시 순위를 매긴다.
	- 논문은 이 방식의 한계를 지적한다.
- **PLAID**: ColBERTv2 의 검색 과정을 최적화한 고성능 검색 엔진이다.
	- 4단계 파이프라인(초기 후보 생성, 가지치기, 재계산 등)으로 후보 수를 점점 줄인다.
	- MUVERA 는 이 구조를 단순화하면서 PLAID 보다 낮은 latency 와 높은 recall 을 얻는 것을 주요 비교 목표로 삼았다.
- **DESSERT**: LSH 기반으로 ɛ-근사 최근접 이웃을 찾는다.
	- PLAID 보다 2–5배 빠르지만 recall 이 더 낮다.
	- MUVERA 는 DESSERT 와 달리 검색 품질을 유지하면서 속도를 높이는 데 집중한다.
