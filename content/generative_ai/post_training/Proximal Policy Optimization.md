# A) RLHF 의 PPO 단계와 보상 모델

PPO 로 액터(actor) 모델을 학습하는 동안 보상(reward) 모델은 학습하지 않고 고정(frozen)해 둔다. LLM 을 사람의 피드백으로 강화학습하는 RLHF 는 보통 세 단계로 진행된다.

## A.1) RLHF 3단계

1. **SFT (Supervised Fine-Tuning, 지도 미세 조정)**: 사전학습된 LLM(Pre-trained LLM)을 사람이 직접 쓴 고품질 질의응답 데이터로 미세 조정한다.
    - 모델이 특정 도메인·스타일에 맞는 기본 지식과 응답 능력을 갖추게 한다.
    - 이 결과 모델이 PPO 단계의 초기 액터가 된다.
2. **보상 모델 학습 (Reward Model Training)**: 사람의 선호도 데이터로 별도의 보상 모델(RM)을 학습한다.
    - 프롬프트 하나에 SFT 모델이 답변을 여러 개 생성한다.
    - 사람(labeler)이 답변을 보고 순위를 매긴다 (예: "답변 A 가 B 보다 좋다", "D 가 C 보다 낫다").
    - RM 은 프롬프트와 답변을 받아 사람이 얼마나 선호할지를 점수(reward)로 낸다.
    - 학습이 끝난 RM 은 사람의 선호를 흉내 내는 심판 역할을 한다.
3. **PPO 강화학습 (Reinforcement Learning with PPO)**: 1단계의 SFT 모델을 액터 정책으로 가져와 RM 점수가 높아지도록 학습한다.
    - 2단계의 RM 은 심판 또는 환경의 일부로 쓰이고, 가중치가 바뀌지 않도록 고정(freeze)한다.
    - 액터가 프롬프트에 대한 답변을 생성한다 (action).
    - 생성한 답변을 고정된 RM 에 넣어 reward 를 받는다.
    - reward 로 액터 정책을 PPO 로 업데이트해, RM 에게 더 높은 점수를 받는 답변을 내도록 학습한다.

## A.2) 보상 모델을 고정하는 이유

- **학습 안정성 (Training Stability)**: 액터가 학습하는 동안 RM 도 바뀌면 액터는 움직이는 목표를 쫓게 되어 학습이 매우 불안정해진다.
    - 목표(RM)가 고정돼 있어야 액터가 일관된 방향으로 정책을 개선한다.
- **명확한 목표 (Clear Objective)**: RM 은 사람의 선호도라는 고정된 기준을 대표한다.
    - 기준을 정해 두고 액터가 그 기준을 만족하도록 학습하면 과정이 더 명확하고 효과적이다.
- **관심사 분리 (Separation of Concerns)**: 선호도 판단 학습(RM)과 선호도 높은 답변 생성 학습(액터)은 서로 다른 과제다.
    - 둘을 나누면 단계마다 한 과제에 집중할 수 있어 문제를 풀기 쉽다.

PPO 단계에서 RM 은 업데이트하지 않고 잘 정의된 보상 함수 역할만 한다. 업데이트 대상은 액터와, 가치(value)를 추정하는 critic 이다.

# B) On-Policy

PPO 는 근본적으로 on-policy 알고리즘이다. 다만 off-policy 의 아이디어를 일부 빌려 데이터 효율을 높였기 때문에 off-policy 로 헷갈리기 쉽다.

## B.1) On-Policy 와 Off-Policy 차이

- **On-Policy (정책 내 학습)**: 지금 정책이 한 행동에서 직접 배운다.
    - 행동을 고르는 정책과, 업데이트에 쓰는 데이터를 만든 정책이 같다.
    - 현재 정책 $\pi_k$ 가 데이터를 모으면 그 데이터로 한 번(또는 몇 epoch) 학습해 $\pi_{k+1}$ 로 업데이트한다.
    - 업데이트가 끝나면 모았던 데이터는 버리고, 새 정책 $\pi_{k+1}$ 이 데이터를 새로 모은다.
    - 매번 데이터를 새로 모아야 해서 데이터 효율이 매우 낮다.
- **Off-Policy (정책 외 학습)**: 과거의 자신이나 다른 정책의 행동을 보고 배운다.
    - 행동을 고르는 행동 정책(behavior policy)과 업데이트 대상인 타깃 정책(target policy)이 다를 수 있다.
    - 과거 경험(다른 정책이 만든 데이터 포함)을 리플레이 버퍼(Replay Buffer)에 쌓아 두고 재사용해 현재 정책을 업데이트한다.
    - 한 번 모은 데이터를 여러 번 재사용하므로 데이터 효율이 높다.

## B.2) PPO 의 On-Policy 학습 루프

PPO 의 기본 학습 루프는 on-policy 구조를 따른다.

1. **데이터 수집**: 현재 액터(정책 $\pi_{\theta_{old}}$)로 경험 데이터(프롬프트, 생성한 답변, reward 등)를 일정량 모은다.
2. **정책 업데이트**: 모은 데이터로 정책 $\pi_\theta$ 를 여러 epoch 동안 최적화한다.
3. **데이터 폐기**: 최적화가 끝나면 1단계에서 모은 경험 데이터를 버린다.
4. **반복**: 업데이트된 정책으로 1단계로 돌아가 데이터를 다시 모은다.

데이터를 버리는 3단계 때문에 PPO 를 on-policy 로 분류한다. Off-policy 알고리즘처럼 과거 경험을 전부 리플레이 버퍼에 쌓아 두고 무작위로 샘플링해 재사용하지 않는다.

## B.3) PPO 의 Off-Policy 성격

PPO 는 한 번 모은 데이터 묶음(batch)을 여러 epoch 의 mini-batch 업데이트에 재사용한다는 점에서 순수한 on-policy 와 다르다.

- 첫 epoch 에서 $\pi_{\theta_{old}}$ 가 $\pi_{\theta_1}$ 로 업데이트된다.
- 두 번째 epoch 에서 $\pi_{\theta_1}$ 을 업데이트할 때도 처음 모은 데이터($\pi_{\theta_{old}}$ 가 만든 데이터)를 그대로 쓴다.

$\pi_{\theta_1}$ 을 $\pi_{\theta_{old}}$ 의 데이터로 업데이트하므로 약간 off-policy 인 상황이 생긴다. PPO 는 이를 두 장치로 다룬다.

- **중요도 샘플링 (Importance Sampling)**: 이전 정책과 현재 정책의 행동 확률 비율 $r(\theta)$ 로 이전 데이터의 가치를 현재 정책에 맞게 보정한다.
- **클리핑 (Clipping)**: $r(\theta)$ 가 너무 커지거나 작아지지 않도록 일정 범위(예: `[0.8, 1.2]`) 안으로 자른다.
    - 정책이 한 번에 크게 바뀌지 않게 막아 학습을 안정시키는 PPO 의 핵심 아이디어다.
    - 정책이 많이 벗어나지 않은(off-policy 정도가 심하지 않은) 범위에서만 이 데이터를 쓰도록 제한하는 셈이다.

## B.4) 보상 모델 고정과 On-Policy 여부

- 보상 모델은 액터의 행동에 점수를 주는 환경(Environment)의 일부일 뿐이다.
- 보상 모델이 고정돼 있다는 사실은 알고리즘이 on-policy 인지 off-policy 인지와 관계없다.

PPO 는 "중요도 샘플링과 클리핑으로 데이터 재사용 효율을 높인 on-policy 알고리즘" 으로 이해하는 편이 가장 정확하다.
