검색 랭킹 모델의 weight 가 1억 개이고, 하나하나가 FP32 (4 바이트) 로 저장돼 있다고 하자.

- weight 만 400 MB 다.
- 점수를 한 번 낼 때마다 GPU 는 이 400 MB 를 메모리에서 읽어 와야 한다.
- 숫자 하나를 1 바이트 (INT8) 로 담으면 100 MB 로 줄고, 읽는 양도 1/4 이 된다.

양자화 (Quantization) 는 이렇게 모델의 숫자를 더 적은 비트로 담는 일이다. 대신 숫자가 덜 정확해지므로, 정확도를 얼마나 지키느냐가 핵심이다. 추론 최적화 전체에서의 자리는 [[Inference Optimization]] 에 있다.

# A) 숫자 형식

아래 그림은 자주 쓰는 숫자 형식이 비트를 어떻게 나눠 쓰는지 보여 준다. 칸 하나가 1 비트다.

![[img-7f2578f465.png]]

**부동소수점은 지수와 가수로 비트를 나눈다.**

- 지수 칸이 많으면 아주 크거나 아주 작은 수까지 담는다 (표현 범위).
- 가수 칸이 많으면 같은 범위 안에서 더 촘촘하게 담는다 (정밀도).

**FP16 과 BF16 은 둘 다 16 비트지만 비트를 나눈 방식이 다르다.**

- FP16 은 가수에 10 비트를 줘서 촘촘하다. 대신 65,504 보다 큰 수를 담지 못해 값이 넘칠 수 있다.
- BF16 은 지수를 FP32 와 같은 8 비트로 둬서 범위가 FP32 와 같다. 대신 덜 촘촘하다.
- 그래서 FP32 로 학습한 모델을 BF16 으로 바꿀 때는 값이 넘칠 걱정이 적다.

**FP8 은 8 비트 부동소수점이다.**

- 지수 4 · 가수 3 (E4M3) 과 지수 5 · 가수 2 (E5M2) 두 종류가 있다.
- H100 같은 최근 GPU 부터 FP8 전용 연산을 지원한다. 자세한 것은 [[FP8 Quantization]].

**INT8 은 −128 부터 127 까지 정수 256 개뿐이다.**

- 0.37 같은 실수를 그대로 담을 수 없다.
- 그래서 "정수 한 칸이 실제로 얼마인지" 를 따로 정해야 한다. 이 눈금을 정하는 일이 좁은 뜻의 양자화다.
- FP32 를 FP16 · BF16 으로 바꾸는 것은 보통 양자화라 부르지 않고 저정밀도 (half precision) 추론이라 부른다. 학습에서 둘을 섞어 쓰는 것은 [[mixed precision]].

# B) 빨라지는 이유

1. **읽고 옮길 바이트가 준다**: weight 를 메모리에서 읽는 시간이 계산 시간보다 긴 층은, 바이트가 1/4 이 되면 그만큼 빨라진다. GPU 메모리와 모델 파일도 작아진다.
2. **같은 시간에 더 많이 곱한다**: GPU 의 행렬 곱 전용 장치 (Tensor Core) 는 낮은 정밀도에서 처리량이 높다. GPU 사양표에서 INT8 처리량은 보통 FP16 의 두 배로 적혀 있다.
3. **한 번에 더 많이 담는다**: 메모리가 남으면 배치를 키워 GPU 를 더 채울 수 있다 ([[Dynamic Batching]]).

**양자화했다고 항상 빨라지지는 않는다.**

- GPU 가 그 형식의 연산을 지원하지 않으면 계산 직전에 다시 FP16 으로 풀어야 한다. 예를 들어 A100 에는 FP8 연산 장치가 없다.
- 정수로 바꾸고 다시 실수로 되돌리는 변환 (quantize · dequantize) 이 층마다 끼면, 그 시간이 이득을 깎는다.
- 병목이 모델 밖 (피처 조회, 네트워크) 에 있으면 응답 시간은 그대로다.

# C) 실수를 정수 눈금에 옮기는 법

0.01 cm 눈금 자로 잰 길이를 1 cm 눈금 자로 옮겨 적는다고 생각하면 된다. 이때 정할 것이 두 가지다.

- **scale ($S$)**: 정수 한 칸이 실제 값으로 얼마인지. 1 cm 자라면 한 칸이 1 cm 다.
- **zero point ($Z$)**: 실제 값 0 이 몇 번 정수에 놓이는지.

실수 $r$ 을 정수 $q$ 로 옮기고, 다시 되돌리는 식은 다음과 같다.

$$
q = \text{round}\left(\frac{r}{S}\right) + Z, \qquad r \approx S\,(q - Z)
$$

예를 들어 어떤 층의 값이 −2.0 부터 6.0 사이에 있고, 이를 INT8 (−128 부터 127 까지) 에 옮긴다고 하자.

- 범위 8.0 을 255 칸으로 나누니 $S \approx 0.0314$ 다. 정수 1 이 실제 값 0.0314 에 해당한다.
- 실제 값 0 은 정수 −64 에 놓인다 ($Z = -64$).
- 6.0 은 127, −2.0 은 −128, 0.0 은 −64 가 된다.
- 127 을 되돌리면 5.99 다. 반올림 때문에 생기는 오차는 많아야 한 칸의 절반 (약 0.016) 이다.

**범위가 0 을 중심으로 대칭이면 zero point 를 0 으로 둔다.**

- weight 는 보통 0 근처에 양쪽으로 퍼져 있어서 대칭 양자화 ($Z = 0$) 를 많이 쓴다.
- ReLU 를 지난 값은 0 이상만 있어서, 범위를 [0, 최댓값] 으로 잡는 비대칭 양자화가 칸을 덜 버린다.

# D) 값 범위 정하기 (calibration)

**weight 는 고정돼 있어서 범위를 바로 알지만, activation 은 입력마다 달라서 미리 측정해야 한다.**

- activation 은 활성화 함수가 아니라, 층과 층 사이를 흐르는 중간 값을 말한다.
- calibration 은 실제 입력을 대표하는 데이터 일부를 모델에 흘려 보내, 층마다 activation 이 어느 범위에 있는지 측정하는 단계다. 재학습은 하지 않는다.
- 랭킹 모델이라면 실제 트래픽에서 뽑은 쿼리 · 후보 쌍을 쓴다. 인기 쿼리만 모으면 드문 쿼리에서 나오는 값의 범위를 놓친다.

범위를 어떻게 잡느냐에 따라 정확도가 달라진다. 아래 그림은 0 근처에 모인 값 400 개와 혼자 튀는 값 8.0 을, 눈에 보이게 칸을 15 개로 줄여 양자화한 결과다. 회색은 원래 값의 분포이고, 파란 선은 정수 칸이 놓인 자리다.

![[img-6ed3de9ea7.png]]

- 가장 큰 값에 범위를 맞추면 8.0 하나 때문에 칸 간격이 1.14 가 된다. 값 대부분이 −1 과 1 사이에 있어서 15 칸 중 4 칸만 쓰인다.
- 99% 의 값이 들어가는 범위 (±1.41) 로 자르면 칸 간격이 0.20 이 되고 15 칸이 다 쓰인다. 대신 8.0 은 1.41 로 잘린다.

**튀는 값 하나를 정확히 담는 것보다 대부분의 값을 촘촘하게 담는 쪽이 정확도를 덜 잃는 경우가 많다.**

- 그래서 최댓값 그대로 (min-max) 보다, 상위 일부를 잘라내는 방식 (percentile) 이나 원래 분포와 가장 비슷해지는 범위를 찾는 방식 (entropy) 을 쓴다.
- 반대로 튀는 값이 중요한 정보를 담는 모델도 있다. LLM 이 그렇다. 이때는 튀는 값만 높은 정밀도로 따로 계산한다 (아래 LLM 절의 bitsandbytes).

**범위를 미리 정해 두는 static 방식과, 요청마다 실행 중에 정하는 dynamic 방식이 있다.**

- static 은 calibration 으로 범위를 미리 정한다. 실행 중 추가 계산이 없다.
- dynamic 은 들어온 값의 범위를 그때그때 계산한다. calibration 이 필요 없지만 그 계산이 매번 붙는다.

# E) scale 을 같이 쓰는 단위

**scale 하나를 얼마나 넓은 범위의 값에 같이 쓰느냐에 따라 tensor · channel · block 단위로 나뉜다.**

- **tensor 단위**: weight 행렬 전체에 scale 하나를 쓴다. 가장 단순하지만, 튀는 값 하나가 행렬 전체의 칸 간격을 정한다 (위 그림의 위쪽 경우).
- **channel 단위**: 출력 채널 (행렬의 행) 마다 scale 을 따로 둔다. 채널마다 값의 크기가 달라서 CNN · linear 층의 INT8 양자화에서 흔히 쓴다.
- **block (group) 단위**: 값 32 · 64 · 128 개씩 묶어 scale 을 둔다. 튀는 값의 영향이 그 묶음 안에 갇힌다. LLM 의 4 비트 weight 양자화 (GPTQ, AWQ) 가 많이 쓴다.

**잘게 나눌수록 정확해지지만 scale 을 저장하고 적용하는 비용이 는다.**

- QLoRA 는 scale 자체를 한 번 더 양자화해 (double quantization) 이 비용을 줄인다.

# F) weight-only 와 activation 양자화

**weight 만 양자화하면 메모리가 줄고, activation 까지 양자화하면 곱셈 자체가 빨라진다.**

- **weight-only**: weight 만 INT8 · INT4 로 저장하고, 계산 직전에 FP16 으로 풀어 FP16 으로 곱한다.
	- 메모리와 읽는 시간은 줄지만 곱셈은 FP16 그대로다.
	- 읽는 시간이 병목일 때 효과가 크다. 배치가 작은 LLM 의 토큰 생성이 대표적이다.
- **weight + activation (W8A8)**: weight 와 activation 을 모두 INT8 로 두고 정수 곱셈 장치로 계산한다.
	- 곱셈 자체가 빨라져서, 배치가 커서 계산이 병목일 때 효과가 크다.
	- activation 범위를 정해야 하므로 calibration 이 필요하다.

# G) PTQ 와 QAT

**PTQ 는 학습이 끝난 모델에 바로 적용하고, QAT 는 양자화를 염두에 두고 학습을 한 번 더 한다.**

- **PTQ (Post-Training Quantization)**: 학습이 끝난 모델에 calibration 만 하고 양자화한다.
	- 학습 데이터와 학습 파이프라인이 필요 없다.
	- 모델에 따라 정확도가 눈에 띄게 떨어질 수 있다.
- **QAT (Quantization-Aware Training)**: 학습 (보통 fine-tuning) 중 forward 에서 값을 양자화했다가 되돌리는 연산 (fake quantization) 을 끼워 넣는다.
	- 모델은 반올림 오차가 있는 상태에서 loss 를 줄이도록 weight 를 맞춘다.
	- 정확도가 PTQ 보다 덜 떨어지지만 학습을 다시 해야 한다.
	- 실제로는 반올림의 기울기가 거의 모든 곳에서 0 이라, backward 에서는 반올림이 없는 것처럼 기울기를 그대로 흘린다 (straight-through estimator).

보통 PTQ 를 먼저 해 보고, 정확도가 모자라면 QAT 로 간다.

# H) 정확도가 떨어질 때의 대응

1. **어느 층이 민감한지 찾는다**: 층을 하나씩만 양자화해 보고 지표가 얼마나 떨어지는지 본다 (sensitivity analysis).
2. **민감한 층은 높은 정밀도로 남긴다**: 문제가 되는 층만 FP16 으로 두고 나머지를 INT8 로 바꾼다. 첫 층과 마지막 층, embedding, LayerNorm · softmax 가 흔히 남겨진다.
3. **scale 을 더 잘게 나눈다**: tensor 단위를 channel 단위로 바꾼다.
4. **calibration 을 바꾼다**: 데이터가 실제 트래픽과 닮았는지 보고, 범위 자르는 방식을 바꿔 본다.
5. **그래도 모자라면 QAT 로 간다.**

**정확도는 원본 모델과 같은 데이터로 나란히 비교한다.**

- 랭킹은 점수 값보다 순서가 중요하다.
- 그래서 점수 차이뿐 아니라 [[Normalized Discounted Cumulative Gain|NDCG]] 같은 순위 지표와, 상위 결과가 원본과 얼마나 달라졌는지를 함께 본다.

# I) LLM 양자화 기법

LLM 은 weight 가 수십억 개라 GPU 메모리에 올리는 것부터 문제가 된다. 그래서 weight 를 4 비트까지 낮추는 weight-only 기법이 많다.

- **GPTQ**: 대표적인 PTQ 기법이다. 층마다 양자화 오차가 출력에 덜 퍼지도록 weight 를 순서대로 고쳐 가며 양자화한다.
- **[[AWQ]] (Activation-aware Weight Quantization)**: activation 이 큰 채널에 곱해지는 weight 가 출력에 더 중요하다고 보고, 그 weight 를 덜 망가지게 양자화한다.
- **bitsandbytes (LLM.int8)**: 튀는 값이 몰린 몇 개 차원만 FP16 으로 계산하고 나머지를 INT8 로 계산한다.
- **QLoRA**: 4 비트 NF4 형식과 double quantization 으로 base 모델을 4 비트로 올려 두고, 그 위에 [[LoRA]] 를 학습한다. 단일 GPU 에서 큰 모델을 fine-tuning 할 수 있게 한다.
- **[[FP8 Quantization]]**: weight · activation · KV cache 를 FP8 로 낮춘다. H100 · H200 같은 GPU 에서 쓴다.

# J) 이진화

양자화를 끝까지 밀면 값을 −1 과 +1 두 개로만 담는 이진화 (Binarization) 가 된다.

- weight 의 부호만 남겨 곱셈이 덧셈 · 뺄셈으로 바뀐다.
- 메모리와 연산은 크게 줄지만 정확도 손실이 커서 일반적인 서빙에서는 드물다.

# 부록: scale 과 zero point 계산

값의 범위 $[r_{\min}, r_{\max}]$ 를 정수 범위 $[q_{\min}, q_{\max}]$ 에 맞출 때 scale 과 zero point 는 다음과 같다.

$$
S = \frac{r_{\max} - r_{\min}}{q_{\max} - q_{\min}}, \qquad Z = \text{round}\left(q_{\max} - \frac{r_{\max}}{S}\right)
$$

본문 예시 ($r \in [-2.0, 6.0]$, INT8) 로 검산하면 다음과 같다.

- $S = 8.0 / 255 \approx 0.03137$
- $Z = \text{round}(127 - 6.0 / 0.03137) = \text{round}(127 - 191.25) = -64$
- $r = 6.0$: $q = \text{round}(191.25) - 64 = 127$
- $r = -2.0$: $q = \text{round}(-63.75) - 64 = -128$
- $q = 127$ 을 되돌리면 $0.03137 \times (127 + 64) \approx 5.99$

scale 을 같이 쓰는 단위 (tensor · channel · block) 는 위 $r_{\min}$, $r_{\max}$ 를 어디에서 찾느냐의 차이다. tensor 단위는 행렬 전체에서, channel 단위는 채널마다, block 단위는 묶음마다 찾아 $(S, Z)$ 를 따로 계산한다.
