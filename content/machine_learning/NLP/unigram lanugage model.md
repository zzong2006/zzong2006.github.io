# A) Unigram Language Model ?

merge 를 기반으로 수행하는 [[Byte-Pair Encoding Tokenization|BPE]] 또는 [[WordPiece]] 방식과 다르게, 유니그램은 가능한 기본 단어들을 모두 깔아놓고 loss 에 가장 영향이 적은 심볼들을 제거한다. 한번에 대략 10~20% 정도의 심볼을 제거하는데, 사용자가 설정한 단어집 크기에 도달할때까지 제거를 수행한다.

이렇다보니 새로운 텍스트에 대해서 토크나이징 하는 방식이 여러개 존재한다. 예를 들면, 유니그램 모델이 학습한 이후 아래와 같은 단어집을 가지고 있다고 가정하자.

```
["b", "g", "h", "n", "p", "s", "u", "ug", "un", "hug"],
```

이 단어집으로 `"hugs"` 는 `["hug", "s"]`, `["h", "ug", "s"]`, `["h", "u", "g", "s"]` 세 가지로 자를 수 있다. 어느 것을 골라야 할까?

유니그램은 토큰마다 확률값을 가지고 있어서, 실제로 토크나이징할 때 가장 높은 확률을 가진 토큰화 결과를 출력한다.

**여기서 "확률" 은 자른 조각들의 확률을 모두 곱한 값이다.** 조각끼리 서로 영향을 주지 않는다고 보고(그래서 unigram) 그냥 곱한다.

- 토큰 확률은 대략 학습 데이터에서 그 토큰이 나온 비율이다. 실제로는 EM 알고리즘으로 추정한다.
- `["hug", "s"]` 의 확률은 $p(\text{hug}) \times p(\text{s})$ 다.
- `["h", "u", "g", "s"]` 는 1 보다 작은 확률을 네 번 곱하므로 보통 더 작아진다. 그래서 긴 조각 몇 개로 자르는 쪽이 대개 이긴다.
- 가능한 분할을 전부 나열하지 않고 Viterbi 알고리즘으로 가장 큰 값을 찾는다.

일반적으로 [[SentencePiece]] 라이브러리에서 사용된다.
