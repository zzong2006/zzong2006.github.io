검색 랭킹 모델이 응답 시간 예산을 넘는다고 하자. 학습된 weight 를 들여다보니 상당수가 0 에 가까운 값이다.

- 0 에 가까운 weight 는 입력에 곱해도 출력에 거의 영향을 주지 않는다.
- 이런 weight 를 없애면 모델이 작아지고 계산이 줄어든다.
- 없앤 뒤 떨어진 정확도는 재학습으로 상당 부분 되돌릴 수 있다.

Pruning 은 이렇게 학습된 신경망에서 기여가 작은 부분을 잘라내는 모델 압축 기법이다. 추론 최적화 전체에서의 자리는 [[Inference Optimization]] 에 있다.

# A) pruning 과정

**한 번에 많이 자르기보다, 조금 자르고 재학습으로 회복하는 일을 되풀이한다.**

1. 학습이 끝난 모델에서 기여가 작은 부분을 고른다.
2. 그 부분을 0 으로 만들거나 구조에서 뺀다.
3. 남은 weight 를 다시 학습해 (fine-tuning) 정확도를 되돌린다.
4. 목표 크기에 닿을 때까지 1 부터 3 까지를 반복한다.

**무엇을 자를지는 "없애도 출력이 덜 변하는 것" 으로 고른다.**

- 가장 단순한 기준은 weight 의 절댓값이다 (magnitude pruning). 작은 것부터 없앤다.
- 채널 · head 처럼 큰 단위를 자를 때는 그 단위가 내는 activation 의 크기나, 없앴을 때 loss 가 얼마나 늘어나는지를 본다.

# B) 비구조적 pruning 과 구조적 pruning

아래 그림은 8×8 weight 행렬 하나를 방식별로 잘랐을 때의 모양이다. 파란 칸은 남은 weight 이고 진할수록 절댓값이 크다. 흰 칸은 0 이 된 weight 다.

![[img-d0d466740e.png]]

**비구조적 pruning 은 weight 를 하나씩 0 으로 만들어서, 행렬 모양은 그대로이고 0 이 여기저기 흩어진다.**

- 그림에서 절댓값이 작은 절반을 0 으로 만들었다. 행렬은 여전히 8×8 이다.
- 개별 weight 단위로 고르므로, 같은 비율을 없앨 때 정확도가 가장 덜 떨어진다.

**구조적 pruning 은 행 · 채널 · attention head · 층을 통째로 없애서, 행렬 자체가 작아진다.**

- 그림에서 절댓값 합이 작은 행 4 개를 지웠다. 출력 뉴런 4 개를 없앤 것과 같고, 행렬이 4×8 이 된다.
- 한 번에 큰 덩어리를 없애므로 정확도가 더 많이 떨어진다.

# C) 비구조적 희소성이 속도로 이어지지 않는 이유

**weight 를 절반 0 으로 만들어도, 일반적인 GPU 연산으로는 실행 시간이 거의 줄지 않는다.**

1. **행렬 모양이 그대로다**: GPU 의 행렬 곱 kernel 은 값이 0 인지 보지 않고 모든 칸을 곱한다. 0 을 곱하는 데도 같은 시간이 든다.
2. **0 을 건너뛰려면 위치를 따로 적어야 한다**: 0 이 아닌 값만 저장하는 희소 형식 (예: CSR) 은 값마다 몇 번째 칸인지를 같이 저장하고 읽는다.
3. **GPU 는 이어진 메모리를 한꺼번에 읽을 때 빠르다**: 0 이 아닌 값이 흩어져 있으면 메모리를 띄엄띄엄 읽게 된다.

그래서 아주 높은 비율로 0 을 만들지 않는 한, 희소 형식의 계산이 그냥 다 곱하는 것보다 느린 경우가 많다.

**구조적 pruning 은 별도 지원 없이 그대로 빨라진다.**

- 결과가 작지만 빈칸 없는 (dense) 행렬이라, 원래 쓰던 행렬 곱 kernel 이 더 작은 일을 할 뿐이다.

**그 중간에 2:4 희소성이 있다.**

- 연속한 weight 4 개마다 정확히 2 개를 0 으로 만든다 (그림의 오른쪽 끝).
- 규칙이 정해져 있어서 NVIDIA Ampere 세대 (A100) 이후 GPU 는 이 모양을 전용 장치로 계산한다. NVIDIA 는 행렬 곱 처리량이 최대 2 배라고 밝힌다.
- 비구조적보다 고를 자유가 적어 정확도는 조금 더 떨어지고, 구조적보다는 덜 떨어진다.

| 방식 | 행렬 모양 | 속도 이득 | 정확도 손실 |
| --- | --- | --- | --- |
| 비구조적 | 그대로 | 일반 GPU 연산으로는 거의 없다 | 가장 작다 |
| 2:4 희소 | 그대로 | 지원하는 GPU 에서 얻는다 | 중간 |
| 구조적 | 작아짐 | 그대로 얻는다 | 가장 크다 |

**비구조적 pruning 도 저장 크기는 줄인다.**

- 0 이 많은 파일은 압축이 잘 된다. 모델을 내려받거나 옮길 때는 이득이 있다.

# D) [[knowledge distillation]] 과 함께 쓰기

**구조적 pruning 은 정확도 손실이 커서, 재학습할 때 distillation 을 붙여 회복시킨다.**

- 잘라내기 전 원래 모델을 teacher 로, 잘라낸 모델을 student 로 둔다.
- 정답 라벨은 클릭했다 · 안 했다만 알려 준다. teacher 의 점수를 따라가게 하면 후보마다 얼마나 그럴듯한지까지 배운다.
- student 가 원래 모델의 weight 를 물려받고 시작하므로, 처음부터 작은 모델을 학습하는 것보다 빨리 회복한다.

NVIDIA 의 Minitron 계열이 이 조합을 크게 밀어붙인 사례다.

- 큰 LLM 을 한 번에 목표 크기까지 줄이는 대신, 조금 잘라내고 distillation 으로 회복시키는 과정을 반복해 여러 크기의 모델을 만든다.
- 처음부터 작은 모델을 학습하는 것보다 훨씬 적은 학습 토큰으로 같은 수준에 닿았다고 보고했다 ([[Compact Language Models via Pruning andKnowledge Distillation]]).

**pruning 은 있던 모델을 깎는 것이고, distillation 은 작은 모델을 새로 가르치는 것이다.**

- distillation 만 쓸 때는 student 의 구조를 따로 정하고 학습을 처음부터 한다.
- pruning 은 student 의 구조와 시작점을 원래 모델에서 얻는 방법으로 볼 수 있다.
