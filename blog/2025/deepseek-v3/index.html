DeepSeek-V3: Intruction

  1. DeepSeek-V2 구조에서 착안하여, DeepSeek-V3는 auxiliary-loss-free 전략을 사용하여 load balancing을 수행하며, load balancing 을 강화하는 과정에서 모델 성능에 미치는 부정적인 영향을 최소화합니다.
  2. 또한, multi-token prediction training objective 를 도입하여 평가 benchmark 에서 전반적인 성능을 향상시킨다. 이는 speculative decoding 을 활용한 inference acceleration 에도 사용할 수 있다.

Efficient Training

  1. FP8 mixed precision training 프레임워크를 도입하고, 초대규모 모델에서 그 효과를 최초로 검증: FP8 연산 및 저장을 지원함으로써 학습 속도를 높이고 GPU 메모리 사용량을 줄일 수 있다.
  2. Pipeline parallelism을 위해 DualPipe 알고리즘을 설계: 이 알고리즘은 cross-node MoE training 에서 발생하는 communication bottleneck 을 해소한다. 즉, pipeline bubble을 최소화하고 computation-communication overlap 을 통해 커뮤니케이션 비용을 줄인다. 이를 통해 모델이 더욱 커지더라도 일정한 computation-to-communication 비율을 유지하면, 노드 간 fine-grained experts를 활용하면서도 all-to-all communication 오버헤드를 거의 0에 가깝게 줄일 수 있다.
  3. InfiniBand(IB) 및 NVLink 대역폭을 최대한 활용할 수 있도록 효율적인 cross-node all-to-all communication 커널을 개발했다.
  4. 메모리 사용량을 최적화하여 비용이 많이 드는 tensor parallelism을 사용하지 않고도 DeepSeek-V3를 학습할 수 있도록 했다. 이러한 최적화 기법을 결합하여 높은 학습 효율성을 달성했다.

사전 학습 동안 DeepSeek-V3는 14.8T의 고품질이고 다양한 토큰을 학습한다. 이후, DeepSeek-V3의 context length를 확장하는 두 단계의 과정을 거친다: 첫 번째 단계에서는 최대 context length를 32K로 늘리고, 두 번째 단계에서는 이를 128K까지 확장한다.

이후, DeepSeek-V3의 base model을 대상으로 Supervised Fine-Tuning(SFT)과 Reinforcement Learning(RL)을 포함한 post-training을 수행하여 모델을 인간의 선호도에 맞추고 잠재력을 더욱 끌어낸다. post-training 단계에서는 DeepSeek R1 시리즈 모델에서 reasoning capability를 distillation을 통해 주입하면서도, 모델의 accuracy와 균형을 신중하게 유지한다.

Training Cost

Pre-training 단계에서 DeepSeek-V3 를 학습하는 데 필요한 비용은 1 trillion token 당 단 180K H800 GPU hour 로, 2048 개의 H800 GPU 를 사용하는 클러스터에서 3.7 일 만에 완료된다. 따라서 pre-training 전체 과정은 두 달 이내에 완료되며, 총 2664K GPU hour 가 소요된다.

여기에 context length 확장을 위한 119K GPU hour 와 post-training 을 위한 5K GPU hour 를 더하면, DeepSeek-V3 의 전체 training cost 는 2.788M GPU hour 에 불과하다. H800 GPU 의 대여 비용을 GPU hour 당 $2 로 가정하면, 총 training cost 는 $5.576M 에 해당한다.

정리하면, 2.664M H800 GPU hour 의 경제적인 비용으로 14.8T token 을 학습하여 DeepSeek-V3 pre-training 을 완료했으며, pre-training 이후의 추가적인 training 단계에서는 단 0.1M GPU hour 만이 필요하다.

Benchmark

DeepSeek-V3-Base 는 특히 code 와 math 분야에서 두각을 나타낸다. GPT-4o 와 Claude-3.5-Sonnet 을 포함한 주요 closed-source 모델들과 비교해도 경쟁력 있는 성능을 보여준다.

MATH-500 benchmark 에서 o1-preview 를 능가하며 강력한 mathematical reasoning capability 를 입증했다.

Architecture

  • 효율적인 inference 를 위한 Multi-Head Latent Attention (MLA)
  • 경제적인 training 을 위해 DeepSeek MoE 를 사용
  • 기타 세부 사항은 DeepSeek-V2 의 설정을 따름

DeepSeek-V3 의 기본적인 구조는 역시나 Transformer 기반이다. DeepSeek-V3 는 DeepSeek-V2 에서 검증된 MLA 와 DeepSeekMoE 를 그대로 채택했다. DeepSeek-V2 와 비교했을 때, 한 가지 차이점은 auxiliary-loss-free load balancing strategy 를 추가 도입했다는 점이다. 이는 load balance 를 보장하려는 과정에서 발생하는 성능 저하를 완화하기 위한 것이다.

아래는 DeepSeek-V3 의 기본 구조를 보여주는 그림이다.

Multi-Head Latent Attention

Attention 부분에서 DeepSeek-V3 는 MLA 를 채택했다. MLA 의 핵심은 inference 시 Key-Value (KV) cache 를 줄이기 위한 low-rank joint compression 기법이다.

주어진 attention layer 에서 𝑡 번째 token 의 attention input 에 대해서, 각 key, value, query 에 대한 개별적인 down projection 을 수행한다. key, value 두 개에 대해 하나의 projection 을 공유하며, projection 사이즈는 매우 작아서 KV cache 크기를 상당히 줄여줄 수 있다.

최종 attention output 을 계산할때 복구를 위해 up projection 을 수행하는데, 이때 복구 방식이 눈여겨 볼만하다. 그 이유는 value 를 제외한 query 와 key 에 대해서 RoPE를 적용한 vector 과 그렇지 않은 vector 를 concatenate 하기 때문이다.

아래 수식을 보면, up projection 을 key 에 적용하기 위해, RoPE 를 적용한 $\mathbf{k}t^{R}$ 과 그렇지 않은 $\mathbf{k}{t, i}^C$ 를 concatenate 하는 것을 볼 수 있다.

추가적으로 query 에 대해서도 마찬가지로 RoPE 를 적용한 $\mathbf{q}t^{R}$ 과 그렇지 않은 $\mathbf{q}{t, i}^C$ 를 concatenate 하는 것을 볼 수 있다.

최종적인 output 계산은 일반적인 transformer 와 차이가 거의 없다.
